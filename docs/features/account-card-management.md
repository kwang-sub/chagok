## 기존 정의와 합의된 기능

### 금융수단 기준정보

- 계좌와 카드를 같은 관리 화면에서 구분해 관리한다. 상세 배치·입력 표현은 기존 화면 명세를 참조한다.
- 계좌는 계좌명·명의·금융기관·계좌유형 등을, 카드는 카드명·명의·카드사·카드유형·결제계좌 등을 관리하는 기존 기획을 따른다. 후보 필드의 필수 여부·검증·민감정보 저장 범위는 아직 미정이다.
- 같은 가계 구성원의 정보를 조회하되, 일반 사용자의 등록·수정·비활성화는 본인 명의 금융수단에 한정한다. 가계 역할과 명의 권한의 충돌·탈퇴 시 처리 등 세부 인가 정책은 후속 설계 대상이다.
- 사용 종료 시 물리 삭제 대신 비활성화한다. 신규 입력에서 선택하지 못하게 하고 과거 이력의 참조는 보존한다. 재활성화 정책은 미정이다.
- 투자 기능에서 계좌를 별도로 중복 생성하지 않고 등록된 계좌를 참조한다. 계좌 자체와 현금·보유자산·평가액을 같은 개념으로 취급하지 않는다.

### 투자 기능과의 책임 분리

- 계좌·카드 관리: 금융수단의 공통 기본정보와 명의·활성 상태를 관리한다.
- 투자 계좌관리: 등록된 투자용 계좌를 참조하고 포트폴리오 구성·목표비중·적용계좌·기준일 초기 보유정보 및 현금을 다룬다.
- 실제 납입·인출과 매수·매도: 별도 사건 이력으로 관리한다. 금융수단 등록이나 설정 변경이 실제 납입·거래를 생성하지 않는다.
- 계좌 기준정보는 투자 기능의 선행 기반이지만 카드 관리 전체 완료를 투자 기능의 필수 선행 조건으로 두지 않는 방향을 제안한다. 구현 순서 승인은 별도다.

## 완료 기준

기존 명세와 합의된 방향을 사용자 동작·조건·결과로 정리한다. 미정인 공급자·카드 상품 자동조회·연동은 완료 조건에 포함하지 않는다.

- [ ] 사용자가 본인 명의 계좌·카드를 등록하면 가계의 조회 가능 범위에서 확인하고 다른 기능에서 같은 금융수단을 참조할 수 있다.
- [ ] 다른 구성원의 금융수단을 조회해도 일반 사용자는 이를 생성·수정·비활성화할 수 없다.
- [ ] 계좌·카드를 비활성화하면 신규 입력 선택에서는 제외되고 기존 이력 조회는 유지된다.
- [ ] 투자 기능에서 계좌를 선택하면 공통 계좌 기준정보를 참조하며 별도 계좌가 중복 생성되지 않는다.
- [ ] 계좌·카드 정보 수정이 실제 납입·매매·현금잔고를 임의 생성하거나 변경하지 않는다.
- [ ] 카드에 결제계좌를 연결하면 카드 상세에서 해당 연결을 확인할 수 있다. 연결 가능 명의·유형·비활성 처리 정책은 확정 후 검증한다.

## 추가 설계가 필요한 사항

### 1. 금융기관·카드사 정보의 의미와 공급 방식

은행·증권사·카드사의 이름과 구분을 제공하는 기준정보 조회와, 사용자 계좌 잔고·거래를 가져오는 금융 연동은 서로 다른 기능이다. 기관 이름 목록을 제공하기 위해 실시간 계좌 연동을 먼저 구현할 필요는 없다.

합의된 초기 방향은 실제 공공 API를 통해 은행·카드사 목록을 확보하고, 개인 계좌·카드는 사용자가 등록하며 번호는 형식만 검사하는 것이다. 아래 금융위원회 API를 원천 후보로 확인했지만, 인증된 응답의 범위·최신성을 검증하기 전 최종 공급자로 확정하지 않는다. 수집한 목록을 내부 기준정보로 제공하는 방식은 운영 제안이다.

- 초기 수집: 공식 기관 목록·공식 코드 자료 등을 후보로 검토하고 은행·증권·카드사의 포함 범위, 이용 조건, 갱신 가능성을 확인한 뒤 수집한다.
- 운영: 검토된 목록을 내부 기준정보로 제공한다. 수동 등록·파일 반영·자동 동기화 중 초기 방식과 관리 권한은 미정이다.
- 외부 조회는 사용자 등록 화면에서 매번 직접 호출하기보다 기준정보 갱신 과정으로 분리하는 방향을 제안한다. 외부 장애 때도 기존 검증 목록을 사용할 수 있도록 한다.
- 기관에는 안정적인 내부 식별자를 사용하고, 외부 코드는 출처별 매핑으로 취급하는 방향을 제안한다. 기관명이나 특정 공급자 코드 하나를 모든 기능의 공통 키로 확정하지 않는다.
- 명칭 변경·합병·폐업·외부 코드 변경 시 기존 개인 금융수단과 거래 참조를 어떻게 보존할지 정한다. 비활성 기관의 신규 선택과 과거 표시를 구분한다.
- 목록에 없는 해외기관·기타 금융수단은 기타 입력, 추가 요청, 사용자 전용 기관 중 지원 방식을 선택해야 한다. 일반 사용자의 자유 입력으로 공통 목록이 오염되지 않게 한다.
- 금융기관과 카드사 역할을 구분하되 동일 기관이 여러 역할을 가질 수 있는지 확인한다. 기관과 카드 브랜드·결제 네트워크를 같은 개념으로 취급하지 않는다.
- 출처·마지막 검증일·활성 상태·별칭 관리, 로고 이용 조건과 미제공 대체 표시를 검토한다. 로고는 등록 기능의 필수 선행 조건으로 두지 않는 것을 제안한다.

외부 자료의 현재 확인 범위: 금융결제원 오픈API 통합포털의 이용절차는 회원가입·이용 신청·계약 절차를 안내하고, 개발자 사이트는 서비스별 API 키와 문서 확인을 안내한다. 이는 사용자 금융정보 연동을 기관명 목록 조회와 같은 가벼운 의존성으로 가정하지 않아야 할 근거다. 해당 서비스나 다른 공급자를 차곡의 기관 기준정보 공급자로 선택한 것은 아니며, 은행·증권·카드사의 통합 목록 제공 여부와 자동 갱신·이용 조건은 미확인이다. 출처 문서명: 금융결제원 오픈API 통합포털 > 이용절차, 금융결제원 오픈API 개발자사이트 > 시작하기(2026-10-05 확인).

### 2. 카드사·카드 상품·사용자 카드의 구분

- 카드사는 발급 주체, 카드 상품은 상품명·혜택 등의 정의, 사용자 카드는 실제 사용하는 개별 금융수단으로 구분하는 방향을 제안한다.
- 초기에는 카드사 선택과 사용자 카드명 직접 입력만 지원할지, 상품 목록까지 제공할지 결정한다.
- 월 실적 기준·혜택·제외 거래·적용 기간은 카드사 이름만으로 자동 확정하지 않는다. 상품별 조건의 수동 설정과 자동 수집 중 지원 범위는 미정이다.
- 재발급·갱신·가족카드·추가 카드의 기존 이력 승계와 별도 등록 기준을 정한다. 결제 네트워크와 카드 발급사를 분리할 필요도 검토한다.
- 파일 가져오기에서 사용자 카드와 매핑하는 기준을 별도로 정하고, 계좌·카드 등록 자체를 거래 파일 가져오기와 같은 기능으로 취급하지 않는다.

### 3. 개인 계좌·카드 식별과 민감정보

- 초기 검증 범위는 계좌번호·카드번호의 패턴 유효성 검사다. 실제 존재·명의 일치·사용 가능 여부를 확인하는 금융사 조회는 제외한다. 형식 통과를 실제 금융수단 확인 완료로 표시하지 않는다.
- 허용 문자·길이·공백/하이픈 처리와 기관별 규칙의 적용 범위는 후속 상세 계약에서 정한다. 확인되지 않은 기관별 정규식이나 길이를 임의 도입하지 않는다. 아래 기관 통계 API를 번호 패턴 규칙의 공급자로 간주하지 않는다.

- 같은 기관에 여러 계좌·카드가 있을 때 별칭 등으로 구별하는 방법과 중복 등록 판단을 정한다.
- 전체 계좌번호·카드번호가 실제로 필요한지 먼저 판단한다. 후면 일부 자리 등 표시용 정보만으로 충분한지는 아직 미정이며, 끝자리만으로 전역 유일성을 보장한다고 가정하지 않는다.
- 저장이 필요하면 접근 범위·마스킹·보관·로그 차단 정책을 별도 설계한다. 인증 비밀번호·CVC·인증코드 등 비밀정보는 이 기능의 입력·저장 대상으로 삼지 않는 방향을 권장한다.
- 금융수단 이름 변경 후 과거 이력에서 당시 이름을 보여주는 방법을 정한다. 현재 이름 참조와 당시 표시값 보존 중 구현 방식은 미정이다.

### 4. 카드 결제계좌와 생명주기

- 결제계좌를 필수로 할지, 같은 명의·같은 가계 중 어떤 범위에서 연결할지 정한다.
- 연결된 계좌를 비활성화할 때 기존 카드와 새 거래 입력에 미치는 영향을 정한다. 카드나 이력을 자동 삭제하지 않는다.
- 결제계좌 변경의 적용일·과거 이력 보존, 결제일 입력 범위와 짧은 달·휴일의 의미를 정한다. 실제 결제 일정 계산 기능을 임의 추가하지 않는다.
- 체크카드와 신용카드의 결제계좌·실적 적용 차이를 별도 정의한다.

### 5. 계좌 유형·통화·현금 및 연금 구분

- 은행·증권 등의 기관 분류, 입출금·증권 등의 계좌 유형, 연금·ISA 등의 제도 구분을 하나의 목록으로 섞을지 분리할지 검토한다. 상세 코드와 지원 범위는 미정이다.
- 투자 사용 가능 계좌의 판정 기준을 정한다. 기관이 증권사라는 이유만으로 모든 계좌를 투자 대상으로 자동 연결하지 않는다.
- 기본 통화와 다중 통화 지원 여부를 정한다. 계좌 등록에는 잔고가 포함되는지, 잔고는 별도 기준일 상태로 입력하는지 책임을 구분한다.
- 화면의 총 잔액 요약은 계좌 목록만으로 계산할 수 있다고 가정하지 않는다. 잔액의 데이터 출처·기준시점·통화 변환·미확인 값 처리와 투자 평가액 중복 집계를 결정해야 한다.

### 6. 권한·실패·연동 정책

- 등록·수정 실패 시 입력 보존, 중복 제출, 권한 변경, 비활성화 충돌, 검색 결과 없음 등의 사용자 결과를 후속 화면 계약으로 정의한다.
- 재활성화, 명의 이전, 가계 이동·탈퇴 때 조회와 변경 권한 및 과거 귀속을 정한다.
- 계좌 자체의 사용 상태와 외부 연동 상태를 분리하는 방향을 제안한다. 연결 실패가 계좌 삭제·비활성화를 의미하지 않게 한다.
- 자동 계좌 연동·실시간 카드 거래 연동은 기존 제품 문서에서 초기 제외 또는 후속 결정이다. 이번 문서화로 해당 범위를 확대하지 않는다.

두 명세의 일반현황 출력에는 `fncoCd`(금융감독원 금융회사코드), `fncoNm`(금융회사명), `crno`(법인등록번호), `basYm`(기준년월)이 있다. `fncoNm`과 `crno`는 명세상 선택 항목이므로 누락값 처리도 필요하다. 기관 이름·코드의 추출 후보이지 현재 사용 가능한 기관만 제공하는 전용 목록 API라는 의미는 아니다.

요청에는 `serviceKey`, `pageNo`, `numOfRows`, `resultType`이 필요하고 `basYm`, `title`은 선택 필터다. 서비스키는 서버에서 관리하고 문서·source·로그에 기록하지 않는다.

명세 확인 당시 두 API는 무료, 이용허락범위 제한 없음, 개발·운영 단계 자동승인으로 안내한다. 이용 조건은 실제 도입 시 다시 확인한다. 카드 API는 상단 데이터 포맷에 JSON을, 요청표에 xml/json을 안내하므로 실제 지원 형식은 인증된 호출로 검증하고 임의 단정하지 않는다.

공식 근거:
- 국내은행 상세 명세: `https://www.data.go.kr/data/15061304/openapi.do`
- 신용카드사 상세 명세: `https://www.data.go.kr/data/15061308/openapi.do?recommendDataYn=Y`

### 적용 방식 제안

- 서버에서 선택한 기준년월·통계 범위의 전체 페이지를 수집하고 정상 응답·누락·중복을 확인한 뒤 기관 목록으로 변환한다. 첫 페이지나 전체 통계 행을 곧바로 기관 선택 목록으로 쓰지 않는다.
- 동일 원천의 `fncoCd` 기준으로 중복을 정리하고, 원천·외부 코드와 차곡 내부 기관 식별자를 연결한다. 금융감독원 코드를 이체용 은행 코드·카드 결제 코드 또는 전체 공급자의 공통 키로 가정하지 않는다.
- 기준년월과 실제 수집시각을 구분한다. 포털의 업데이트 주기 표기를 최신 기관 목록·영업 상태의 보장으로 해석하지 않는다.
- 갱신 실패·부분 응답·빈 결과만으로 기존 목록이나 연결된 개인 금융수단을 삭제·비활성화하지 않는 방향을 제안한다. 초기 목록 미확보 및 기존 목록 사용 시의 안내는 후속 화면 계약으로 정한다.

### 미검증 및 후속 확인

- 서비스키를 사용하는 인증된 API 호출은 수행하지 않았다. 현재 응답·최신 기준년월·기관 수·실제 누락 여부는 미검증이다.
- 국내은행 API가 우체국·상호금융·저축은행 등 원하는 계좌 등록 범위를 포함하는지, 카드 API가 은행계 발급사 등 원하는 카드 등록 범위를 포함하는지 실제 목록 대조가 필요하다. 부족한 범위의 보완 원천은 미정이다.
- 증권사 목록은 이번 확인 대상에 포함하지 않았다. 투자계좌 기능을 위해 별도 원천과 범위를 확인해야 한다.
- 현재 영업 여부·합병·폐업 판정, 기관별 번호 패턴·카드 상품·혜택 제공 여부는 이번 명세로 확인하지 않았다.
- 인증된 전체 응답의 범위와 최신성을 확인한 뒤 공급자 확정·갱신 주기·예외 정책을 정한다. API 존재 확인만으로 실제 목록 수집·적용 완료라고 표시하지 않는다.

### 추가 완료 기준

- [ ] 검증된 공공 API 데이터가 적용되면 사용자가 은행·카드사 목록을 검색·선택할 수 있고 기준년월과 수집 상태를 확인할 수 있다.
- [ ] 같은 기관이 여러 통계 행·페이지에 있어도 선택 목록에서 중복 표시되지 않는다.
- [ ] 외부 갱신 실패 시 기존 금융수단 참조를 보존하고 확정된 정책에 따라 안내한다.
- [ ] 번호가 확정된 형식 규칙을 위반하면 오류를 안내하고, 형식을 통과해도 실제 존재·명의 확인을 수행한 것으로 표시하지 않는다.

## 미정 사항과 향후 아이디어

은행·카드사 목록의 실제 공공 API 적용과 번호의 패턴 검사만 수행하는 초기 방향은 합의되었다. 원천 후보는 위 공식 명세로 확인했다. 최종 공급자·갱신 방식, 지원 국가와 기관 범위, 기타 기관 처리, 증권사 원천, 카드 상품 지원 여부, 번호 형식 규칙·저장 범위, 결제계좌 관계, 계좌 유형·통화·잔액 책임, 재활성화 및 명의·가계 변경 정책은 아직 미정이다. 문서화는 구현 실행 승인이나 공급자 최종 선정으로 취급하지 않는다.

우선 결정할 순서는 기관 목록의 초기 운영 방식 → 개인 금융수단의 최소 입력 및 식별정보 → 유형·명의·활성/연결 정책 → 투자 및 거래 참조 계약을 제안한다.
