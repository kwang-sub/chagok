# 투자 관리 — 현재 구현 기준과 개선 논의

## 목적

사용자가 투자자산의 보유·평가 현황을 확인하고, 투자금 투입부터 제안 확인·실행 결과 추적까지 하나의 흐름으로 관리하도록 한다. 투자 분석은 장기 성과와 위험을 이해하는 별도 화면으로 설계되어 있다.

이 문서는 기능의 목적·범위·현재 구현 근거와 개선 논의를 관리한다. 버튼 위치, 노출 조건, 입력·상태 동작의 상세 계약은 관련 `screen-spec.md`를 참조한다. 현재 코드의 UI 예시를 실제 데이터 기능 또는 새 제품 결정으로 승인하지 않는다.

- 판단: 포트폴리오와 투자 내역의 UI 및 로컬 fixture 기반 동작은 존재한다. 실제 투자 데이터 조회·저장·상태 변경·시뮬레이션은 해당 UI에서 연결되지 않았고, 투자 분석은 확인한 프론트 route/feature 범위에 구현이 발견되지 않았다. 따라서 전체 투자 관리 기능을 구현 완료로 표시하지 않는다.
- 검증 한계: 이번 확인은 source와 기존 작업 근거의 대조다. 새 build/test/browser 실행은 하지 않았으며, 기존 테스트 파일의 존재를 현재 PASS 증거로 간주하지 않는다.

## 기존 문서에 정의된 기능과 완료 기준

아래는 기존 제품·화면 문서에 정의된 기능이다. 이번 문서화로 미확정 세부 동작이나 전체 제품 동작을 새로 승인하지 않는다. 체크박스는 실제 데이터 기반 기능의 완료 여부이며, UI fixture 구현만으로 체크하지 않는다.

- [ ] 사용자가 포트폴리오를 조회하면 실제 보유자산 기준 평가·원금·손익·배분·가격 기준시점을 확인할 수 있다.
- [ ] 투자 예정 회차를 진행·보류·건너뛰면 해당 회차의 결과가 보존되고, 보류 후 재실행 및 반복 계획 유지 규칙을 충족한다.
- [ ] 사용자가 추가 납입을 등록하면 기존 정기 계획을 변경하지 않는 독립 투자금 투입 건이 생성된다.
- [ ] 사용 가능한 투자금으로 제안을 조회하면 계산에 사용한 가격·비중의 기준과 제안 결과를 확인하고 실제 주문과 구분할 수 있다.
- [ ] 사용자가 외부 증권사에서 거래한 뒤 결과를 기록하면 투자 제안과 실제 결과를 구분해 확인할 수 있다. Funding 전체 완료 기준은 미정이다.
- [ ] 사용자가 보유정보를 보정하면 확정된 검증·저장 정책에 따라 본인 계좌의 수량·평균매입가·목표비중이 반영된다.
- [ ] 투자 내역을 필터링하면 동일 조건의 목록과 요약을 보고, 상세에서 제안과 실행 결과를 확인한다.
- [ ] 과거 투자 건으로 다시 투자하면 확정된 복사·생성 정책에 따라 새 건을 만들고 원본 이력은 보존한다.
- [ ] 같은 가계 구성원의 투자정보는 조회하고, 생성·변경은 해당 계좌 명의자에게 제한된다.
- [ ] 투자 분석에서 선택 기간의 성과·위험·기여도·상관관계·리밸런싱 효과를 확인하고, 계산 불가·부분 분석·가격 기준시점을 구분한다. 분석 동작은 DRAFT이며 세부 기준은 승인 전이다.

## 확인된 주의 사항

### 예시 보유정보의 숫자 형식 불일치

`fixtures.ts:7`, `:8`, `:11`의 일부 손익 문자열에는 숫자가 아닌 `*`가 포함되어 있다. `holdings.tsx:13`의 종목 상세는 해당 값을 `won()`으로 표시하고, `format-finance.ts:3`은 잘못된 숫자 문자열에 예외를 던진다.

## 합의된 개선 방향 — 거래 기록과 투자 설정 분리

아래는 사용자와 합의한 기능 방향이며 아직 구현되지 않았다. 기존 화면 명세의 상세 계약이나 구현 실행 승인을 대신하지 않는다.

- 실제 매수 내역을 입력·저장하면 보유수량·평균매입가에 자동 반영한다. 동일 종목을 여러 날짜·가격으로 분할 매수할 수 있으며 각각의 실제 거래를 기록한다.
- 투자 화면은 현재 비중과 참고용 추가 매수/매도 제안 수량을 확인하고 사용자가 거래를 기록하는 흐름을 중심으로 한다. 제안 전량 실행, 추가 매수, 리밸런싱, 잔액 소진을 강제하지 않는다.
- 일반 거래는 투자금 투입 건을 먼저 선택하지 않고 기록할 수 있게 하고, 필요한 경우 투자금 투입 건에 연결하는 방향으로 한다.
- 매수/매도와 일반/리밸런싱 목적은 구분한다. 목적의 기본 선택·사용자 변경 및 분류 방식은 상세 명세에서 확정한다.
- 목표비중·포트폴리오 구성·적용계좌 설정은 거래 기록과 분리하여 별도 투자 계좌관리 항목에서 관리한다. 기존 계좌·카드 기준정보를 재사용하며 새로운 계좌 식별 체계를 임의로 만들지 않는다.
- 투자 화면에서는 설정된 목표비중·적용 범위와 현재비중을 참고할 수 있게 하되, 설정 관리와 실제 거래 기록의 책임을 구분한다.

### 현재 화면과의 차이

- 계좌·카드 관리 명세는 금융수단의 기준정보를 별도 화면에서 관리하도록 정의한다. 투자계좌는 투자 화면과 동일한 계좌 식별자를 사용하도록 명시한다 (`../ui/screens/account-card-management/screen-spec.md:27`, `:68`).
- 그러나 해당 명세에는 투자 포트폴리오 구성·목표비중·적용계좌 설정 관리가 별도 기능으로 정의되어 있지 않다.
- 현재 투자 UI에서는 목표비중 보정 입력이 종목 상세에 남아 있다 (`../../chagok-frontend/src/features/investment/holdings.tsx:13`). 실제 저장은 미연결이다.
- 현재 계좌·카드 메뉴는 `/preview/cards`로 연결되고, 해당 route는 미구현 안내 화면이다 (`../../chagok-frontend/src/app/preview/[section]/page.tsx:6`). 따라서 투자 설정의 별도 관리가 이미 구현되었다고 판단하지 않는다.

## 추가 기능 방향 — 자금 이력·거래 이력·기준일 보유현황

사용자의 추가 문서화 요청에 따라 대화에서 정리한 방향을 반영한다. 기능 방향의 합의와 상세 정책 제안을 구분하며, 이 절은 구현·API·데이터 모델 변경의 실행 승인이 아니다.

### 자금 납입과 자산 거래의 분리

- 실제 투자 자금 납입·인출 내역과 종목 매수·매도 내역을 독립적으로 관리한다. 납입액과 매수액을 같은 의미로 집계하지 않는다.
- 납입만 기록하고 매수하지 않을 수 있으며, 매수 기록 때문에 실제 납입 내역을 자동 생성하지 않는다. 정기 예정일 도래 역시 실제 납입 증거가 아니다.
- 한 납입분으로 분할 매수하거나 여러 납입분·기존 현금으로 한 번에 매수할 수 있다. 납입과 거래의 일대일 연결을 강제하지 않는다.
- 매도 대금은 계좌 안의 현금으로 남거나 재투자될 수 있으므로 외부 인출과 구분한다.
- 계좌 간 이체는 실제 납입·인출과 유형을 구분하고, 분석에 포함한 계좌 범위에 따라 외부 이동인지 내부 이동인지 판정하는 방향으로 한다. 상세 집계 정책은 미정이다.
- 배당·이자·수수료·세금 등의 현금 변동은 사용자 납입과 구분할 필요가 있다. 초기 지원 범위와 입력 방식은 아직 미정이다.

### 실제 납입 기록 기능

- 실제 납입일·투자계좌·통화·금액을 기록하고 과거 납입 내역도 등록할 수 있도록 한다. 화면별 입력 배치와 검증 조건은 후속 화면 명세에서 정한다.
- 실제 납입 내역의 조회·정정·취소를 지원하는 방향으로 하되, 정정 전 기록 보존·중복 방지·잔고 재계산 정책은 별도 확정한다.
- 인출·계좌 간 이체를 별도 유형으로 다루며, 이를 납입이나 투자 수익으로 오인하지 않게 한다.
- 정기 납입 계획은 미래 일정이고 실제 납입 기록은 발생한 자금 이동이다. 계획과 실제 발생 여부를 분리한다.
- 기존 추가 납입의 시뮬레이션 연결은 선택적 흐름으로 조정할 대상이다. 실제 납입 저장에 시뮬레이션·매수 실행·전체 투자 건 완료를 요구하지 않는다.

### 과거 거래를 모르는 사용자의 시작 방법

- 과거 납입 내역은 알고 있는 실제 날짜와 금액으로 기록하고, 과거 매수·매도 내역을 모두 입력하지 않아도 기준일 보유현황으로 시작할 수 있게 한다.
- 기준일에 종목별 보유수량·알고 있는 평균매입가·계좌 현금 등을 등록한다. 평균매입가 미확인값을 0이나 기준일 가격으로 자동 대체하지 않는다.
- 기준일 보유현황 등록은 실제 매수 거래가 아니다. 등록일의 가상 일괄 매수, 신규 납입 또는 현금 차감을 생성하지 않는다.
- 취득원가용 평균매입가와 기준일 이후 성과 측정용 가격·평가액은 목적을 구분한다. 구체적인 저장 모델·평가 정책은 후속 설계 대상이다.
- 기준일 이후에는 실제 거래·자금 이동을 기록한다. 기준일 이후 분석도 필요한 평가·가격·현금흐름 데이터가 확보된 범위에서만 제공한다.

### 초기 보유정보 수정과 거래 정정

대화에서 제안한 보정 방식이며 상세 적용 정책은 아직 미정이다.

- 투자 계좌관리의 보유자산 상세에서 초기 보유정보 수정과 거래 내역 정정에 각각 진입하는 방향을 권장한다.
- 최초 수량·평균매입가 오류는 초기 보유정보에서, 매수·매도 입력 오류는 해당 거래에서 정정한다. 현재 잔고만 덮어써 원인 기록과 불일치하게 만들지 않는다.
- 변경이 이후 보유정보·성과에 미치는 영향과 재계산 범위를 안내하는 방향을 권장한다. 변경 전후 미리보기는 제안이며 세부 화면 계약은 미정이다.
- 거래 오류가 아닌 잔고 불일치의 별도 보정은 향후 후보다. 초기 보유정보 수정과 거래 정정의 지원 범위부터 확정하며, 무제한 잔고 덮어쓰기를 이번 합의로 간주하지 않는다.

### 분석 가능 범위와 데이터 부족 안내

아래는 기능 기획상의 제공 조건이다. 계산식·기간 경계·수수료·환율·데이터 충족 판단·XIRR 해 존재 및 실패 처리는 별도 설계·검증하며, 현재 계산 구현이나 결과 정확성을 선언하지 않는다.

- 전체 투자손익과 금액가중수익률(XIRR)은 분석 시작 자산, 실제 외부 자금 흐름, 기준시점 총자산 등 필요한 입력이 확보되면 과거 개별 매매 내역 없이 제공할 수 있는 후보로 둔다. 총자산에는 계좌 현금을 포함하며 납입만으로 모든 수익률을 계산 가능하다고 표시하지 않는다.
- 외부 인출·외부 지급 배당 등 필요한 자금 흐름이 누락된 경우 누락 여부와 한계를 표시한다. 계좌 현금이나 가격을 모르면 확인된 값만으로 정확한 전체 성과를 보장하지 않는다.
- 과거 평가액·보유·거래 이력이 부족한 기간의 시간가중수익률, 자산 추이, 최대낙폭, 종목별 과거 기여도는 정확히 복원했다고 표시하지 않는다. 지표마다 필요한 데이터와 계산 가능 기간을 구분한다.
- 현재 보유종목의 평가손익은 원가를 확인할 수 있는 범위에서 제공하며, 과거 매도분을 포함한 누적 종목 성과나 기간별 기여도와 구분한다.
- 현재 보유비중을 과거 전 기간에 적용한 값을 실제 기여도로 표시하지 않는다. 근거가 부족한 과거 종목별 기여도는 데이터 부족으로 안내한다.
- 지표별 분석 시작일·기준일·데이터 부족 이유를 표시한다. 추정 분석 제공 여부와 표시 방식은 아직 미정이다.

### 기존 기획과 데이터 모델의 연결

- 기존 정기 계획·추가 납입 기획은 투자 실행 예산과 회차 관리 중심이다. 지금 합의한 실제 납입 기록과 거래 기록의 독립 관리에 맞춰 후속 화면 명세 조정이 필요하다.
- 기존 `investment_funding.amount`는 실행 예산이며 실제 외부 납입 증빙이 아니다. `processed_on`도 실제 현금흐름일과 구분한다 (`../data/schema.dbml`).
- 기존 `investment_cash_flow`는 실제 외부 입출금·내부 이동 사건을 표현하며 Funding 연결은 선택적이다 (`../data/investment-model.md`). 실제 납입 기능은 이 책임을 우선 참고한다.
- 기존 `investment_execution_result`는 제안별 현재 처리 결과이고 체결 원장이 아니다. 독립 거래·분할 거래·정정·기준일 보유현황의 요구사항을 현재 모델이 이미 충족한다고 판단하지 않는다. 논리 모델 영향은 별도 설계에서 확인하며 이번 문서화로 DBML을 변경하지 않는다.

### 구현 의존관계 제안

1. 계좌·카드 관리 중 투자에 필요한 계좌 기준정보와 명의·권한
2. 투자 계좌관리의 포트폴리오·목표비중·적용계좌 및 초기 보유정보·현금
3. 실제 납입·인출 기록과 실제 매수·매도 기록의 독립 기능
4. 확보된 데이터 범위의 투자 분석

카드 관리 전체 완료를 투자 기능의 선행 조건으로 두지 않는다. 위 순서는 기획상 의존관계 제안이며, Task 분해·작업 순서·검증 계획 승인은 별도로 진행한다.

### 추가 완료 기준

- [ ] 사용자가 실제 납입일과 금액을 저장하면 매수 없이도 납입 내역을 조회할 수 있고, 정기 예정 회차와 실제 발생 내역이 구분된다.
- [ ] 여러 납입과 여러 거래를 독립적으로 기록할 수 있으며, 거래마다 납입 건 연결을 요구하지 않는다.
- [ ] 과거 거래가 없는 사용자가 기준일 보유현황으로 시작해도 가상 매수·납입·중복 현금 차감이 생기지 않는다.
- [ ] 초기 보유정보 오류와 실제 거래 오류를 원인별로 정정하고, 확정된 정책에 따라 보유정보·분석에 반영한다.
- [ ] 분석 지표마다 데이터 충족 여부와 제공 기간을 표시하고, 과거 이력 부족을 실제 종목별 기여도로 대신 표시하지 않는다.

## 미정 사항과 개선 후보

아래는 논의용 제안이며 이번 구현 완료 기준에 추가되지 않는다. 사용자 결정 전 구현하지 않는다.

### 우선 논의 제안: 실제 투자금 실행을 최소 기능으로 완성

1. 보유정보 예시의 숫자 불일치를 별도 수정 범위로 다루고, 현재 UI의 기본 사용 가능성을 확인한다.
2. 실제 데이터 기능은 계좌 기준정보·투자 설정을 기반으로 실제 납입과 거래를 독립적으로 기록하는 방향으로 구체화했다. 기존 Funding 중심 흐름은 필수 경로가 아닌 선택적 연결로 재검토한다.
3. 실제 매수 저장 시 보유수량·평균매입가 자동 반영은 위 합의로 확정했다. 기존 수동 최종 보정과의 관계 및 정정 정책은 남은 결정으로 다룬다.
4. 명의자 권한과 저장 실패·중복 제출·일부 실행의 완료 기준을 먼저 확정한다.

### 투자 내역 개선 후보

- 기본 조회 기간을 현재 연도/최근 기간/전체 중 무엇으로 할지 결정한다. 현재 2025년 고정값은 fixture 관찰값일 뿐이다.
- `다시 투자하기`와 `복사하여 새로 등록`의 목적을 구분하거나 하나로 통합할지 결정한다. 기존 건 이어하기는 새 건 생성과 구분한다.
- 실제 저장 전 확인, 취소 시 원본 보존, 중복 생성 방지와 상세 복귀를 명확히 한다.
- 명의 필터, 비활성 건 조회, 정렬·페이지 이동은 필요한 범위만 별도로 결정한다.

### 투자 분석 개선 후보

- 전체 분석 항목을 한 번에 구현하기보다 실제 데이터와 계산 근거가 준비된 성과·가격시점·분석 불가 안내부터 제공할지 논의한다. 우선 지표 목록은 아직 미정이다.
- 실제 사용자 성과와 전략 성과를 혼동하지 않도록 지표명·설명·기준기간을 정한다. 새로운 계산식은 이번 문서에서 확정하지 않는다.
- 모바일에도 실제 수익률을 제공할 위치, 기본 분석 기간, 부분 분석/오래된 가격 처리 방식을 결정한다.
- Benchmark·Rolling 지표 등 기존 후속 확장은 초기 범위와 분리한다.

### 결정이 필요한 질문

- 계좌 기준정보와 투자 설정 이후 실제 납입·거래 기록의 구현 단위를 어떻게 나눌 것인가? 카드 관리 전체 완료는 투자 기능의 필수 선행 조건으로 두지 않는 방향을 제안했다.
- 실제 거래 입력 항목과 매도·수수료·환율·정정 정책을 어떻게 정할 것인가? 실제 매수 기록에 따른 자동 반영과 분할 매수 지원은 합의되었다.
- 선택적으로 연결한 투자금 투입 건의 상태와 실제 거래 기록을 어떻게 연결할 것인가? 보유정보 반영은 전체 건 완료를 기다리지 않는다.
- 재투자는 새 건의 입력 초안을 만드는 기능으로 정의할 것인가?
