상위 명세: [계좌·카드 화면군](../screen-spec.md)

Reference: `./reference.png` — 업로드 예정. 현재 이 폴더에는 설명 초안만 추가한다.

이미지 업로드 방법: [화면별 이미지 안내](../README.md)

## 화면 목적

선택한 계좌의 기본정보를 조회하고, 본인 계좌에 한해 수정 또는 비활성화를 수행한다. 계좌의 다른 기능별 사용처를 집계하거나 투자·거래·현금잔고를 변경하는 화면은 아니다.

## Design Reference / Viewport

흰 배경, 녹색 주요 액션, 민트색 사용중 배지 등 기존 차곡 시안의 톤을 유지한다. Desktop 상세는 별도 화면을 기본으로 하고 **요약과 기본정보를 하나의 상세 카드 안에 배치**한다. 상단 요약 카드와 하단 기본정보 카드를 따로 만들지 않는다. Mobile은 동일한 정보 순서를 세로로 배치한다.

```text
계좌·카드 > 계좌 상세

[하나의 상세 카드]
  아이콘  계좌명                          사용중 배지
          금융기관 · 계좌유형
  ------------------------------------------------
  금융기관 / 계좌유형 / 마스킹 식별정보 / 개설일
  메모
  ------------------------------------------------
  목록으로                          비활성화   수정
```

상단 아이콘·제목·요약과 본문 사이의 얇은 구분선은 허용하지만 별도 카드나 별도 사용상태 블록으로 나누지 않는다.

## 표시 정보

| 항목 | 표시 원칙 |
| --- | --- |
| 계좌명 | 상단 대표 제목. 같은 이름을 기본정보에 불필요하게 반복하지 않는다. |
| 금융기관·계좌유형 | 등록된 기준정보를 표시한다. 시안의 은행/증권/연금 등 분류를 그대로 확정 코드로 사용하지 않는다. |
| 사용상태 | 상단에 사용중 또는 비활성 배지를 한 번만 표시한다. 하단 사용상태 탭·카드·행은 만들지 않는다. |
| 계좌 식별정보 | 목록과 동일한 마스킹 정책을 따른다. 시안의 전체 번호 표시는 전체 번호 조회·저장 승인으로 해석하지 않는다. |
| 개설일·메모 | 등록 정보가 있으면 표시하고 없으면 미입력으로 구분한다. 필수 여부와 길이 제한은 후속 확정이다. |
| 명의 | 수정 가능한 입력·선택 UI는 없다. 가계 전체 조회 시 필요한 소유자 구분은 읽기 전용 정보로만 제공할 수 있다. |
| 현재 잔액 후보 | 출처·기준일·통화가 확정된 경우에만 읽기 전용으로 표시한다. 미확인 금액은 0으로 채우지 않는다. |

## 기능 → UI → 사용자 동작 → 결과

| 기능 | 노출 UI / 동작 | 정상 결과 | 조건·예외 |
| --- | --- | --- | --- |
| 목록 복귀 | 하단 목록으로 / Mobile 뒤로가기 | [계좌 목록](../account-list/screen-spec.md) 복귀 | 가능한 경우 기존 검색·필터·페이지를 복원한다. |
| 수정 | 하단 수정 버튼 | 선택한 계좌 ID로 [계좌 수정](../account-form/screen-spec.md) 진입 | 본인 계좌에서만 노출한다. 클릭 시에도 서버에서 변경 권한을 확인한다. |
| 비활성화 요청 | 하단 비활성화 버튼 | 대상 계좌명과 영향 안내가 있는 확인창 표시 | 사용중인 본인 계좌에서만 제공한다. 즉시 삭제하거나 다른 정보를 연쇄 삭제하지 않는다. |
| 비활성화 취소 | 확인창 취소 | 변경 없이 상세 유지 | 기존 사용상태가 유지된다. |
| 비활성화 확정 | 확인창 비활성화 확인 | 성공 시 상태 배지와 목록 상태 갱신 | 처리 중 중복 요청을 막고, 실패 시 성공으로 표시하지 않는다. 충돌·권한 변경 시 최신 상태와 안내를 제공한다. |
| 오류 재시도 | 재시도 | 동일 계좌 상세 재조회 | 존재하지 않거나 더 이상 조회 권한이 없으면 재시도만 반복시키지 않고 목록 이동을 제공한다. |

확인 안내 초안: “이 계좌를 비활성화하면 새 거래·투자 입력에서 선택할 수 없습니다. 기존 거래와 투자 이력은 유지됩니다.”

## 제거한 영역과 동작

- 상세 상단 수정 버튼과 설정/더보기 버튼을 제공하지 않는다. 주요 액션은 하단에만 둔다.
- 하단 사용상태 영역을 제거한다. 상태는 상단 배지 한 곳에서 확인한다.
- 활용현황, 자동이체 사용 건수, 목표 자금, 기타 참조 건수, 연결 관리 영역을 제공하지 않는다.
- 통장 용도는 분리 시안에 나타난 추가 항목일 뿐 확정 입력 필드가 아니다. 필요하면 기존 메모로 표현하고 별도 필드는 후속 검토한다.
- 실시간 금융 연동, 거래 생성, 잔액 직접 수정, 계좌 삭제, 재활성화 기능은 이번 상세 초안으로 추가하지 않는다.

## Responsive / Permission

Desktop은 하나의 정보 카드와 하단 목록으로·비활성화·수정 액션을 사용한다. Mobile도 같은 정보와 권한을 제공하되 액션 폭과 배치는 작은 화면에 맞춘다. 고정 하단 액션을 사용하면 본문 마지막 항목을 가리지 않아야 한다.

다른 가계 구성원의 계좌는 조회 전용이며 수정·비활성화 버튼을 숨긴다. 명의는 입력받지 않고, 조회 사용자가 바뀌어도 기존 계좌의 소유자를 자동으로 바꾸지 않는다. 이미 비활성인 계좌의 기본정보 수정 허용 범위와 재활성화는 미정이므로 추가 액션으로 단정하지 않는다.

## 상태와 예외

Loading 중에는 샘플 계좌 정보를 실제 조회값처럼 표시하지 않는다. 조회 오류는 재시도, 존재하지 않음은 목록 복귀, 권한 상실은 접근 제한 안내로 구분한다. 비활성화 중에는 동일 동작의 중복 제출을 막고 완료 전 사용중 배지를 임의로 제거하지 않는다. 비활성화된 계좌의 과거 이력은 유지한다.

## Data / API Dependency

계좌 상세, 로그인 사용자·가계 조회/변경 권한, 금융기관·유형 표시정보, 비활성화 결과가 필요하다. 다른 도메인의 활용 건수 집계 API는 필요하지 않다. 현재 잔액 표시는 별도 조회 계약 확정 사항이다. endpoint·응답 필드·충돌 제어 방식은 후속 설계에서 정한다.

## Acceptance Criteria

- [ ] Desktop의 계좌 요약과 기본정보가 하나의 상세 카드로 표시된다.
- [ ] 상단 수정·설정/더보기 버튼과 하단 사용상태 영역이 없다.
- [ ] 사용상태 배지는 한 번만 표시되고 주요 액션은 하단에만 존재한다.
- [ ] 다른 구성원 계좌는 조회만 가능하며 변경 요청도 서버에서 차단한다.
- [ ] 비활성화 확인·취소·성공·실패·중복 요청 상태가 정의대로 동작한다.
- [ ] 활용현황과 잔액·거래 변경 기능을 생성하지 않는다.
- [ ] Desktop/Mobile에서 마스킹, 목록 복귀, 작은 화면의 액션 접근성이 검증된다.

위 항목은 구현 후 검증할 기준이며 이번 변경에서 application/browser 검증을 실행한 것은 아니다.
