## 화면 목적

선택한 카드의 기본정보를 확인하고 본인 카드에 한해 수정·비활성화를 수행한다. 카드의 결제계좌를 연결하거나 다른 기능의 활용 건수를 집계하는 화면은 아니다.

## Design Reference / Viewport

계좌 상세와 같은 흰색·녹색·민트 톤을 사용한다. Desktop은 **카드 요약과 기본정보가 하나의 상세 카드**로 이어지는 별도 화면이다. 상단 요약 카드와 하단 정보 카드를 분리하지 않는다. 카드 상단에는 조회 정보와 상태 배지만 두며 수정·설정/더보기 버튼을 배치하지 않는다.

```text
계좌·카드 > 카드 상세

[하나의 상세 카드]
  카드 아이콘  카드명                     사용중 배지
               카드사 · 카드유형
  ------------------------------------------------
  카드사 / 카드유형 / 마스킹 식별정보 / 결제일
  메모
  ------------------------------------------------
  목록으로                          비활성화   수정
```

Mobile도 같은 정보 순서를 세로로 사용한다. 상단의 상태 배지와 중복되는 하단 사용상태 영역을 만들지 않는다.

## 표시 정보

| 항목 | 표시 원칙 |
| --- | --- |
| 카드명 | 상단 대표 제목. 사용자 별칭이며 자동 조회된 카드 상품 정보라고 단정하지 않는다. |
| 카드 아이콘 | 실제 상품 이미지가 없으면 공통 카드 아이콘을 사용한다. 상품 이미지 수집을 필수 의존성으로 두지 않는다. |
| 카드사·카드유형 | 등록된 카드사와 유형 기준정보를 표시한다. |
| 사용상태 | 상단 사용중/비활성 배지 한 곳에서만 표시한다. |
| 카드 식별정보 | 확정된 마스킹 정책에 따라 표시한다. 전체 번호 공개 버튼을 임의로 추가하지 않는다. |
| 결제일 | 사용자가 설정한 값이 있는 경우 표시하는 후보 항목. 실제 청구일·출금일 자동 계산을 의미하지 않는다. 카드유형별 적용과 필수 여부는 미정이다. |
| 메모 | 입력된 설명을 표시한다. 비어 있으면 미입력으로 구분한다. |
| 명의 | 수정 가능한 입력·선택 UI는 없다. 가계 전체 조회에서 소유자 구분이 필요하면 읽기 전용으로 표시할 수 있다. |

## 제외 및 시안 정합성

- 명의 설정, 결제계좌·연결계좌 표시/선택/변경, 활용현황과 참조 건수는 제외한다.
- 상세 상단 수정·설정/더보기 버튼과 하단 사용상태 탭·카드·행을 제공하지 않는다.
- 분리 시안에 추가된 유효기간·발급일·연회비·카드 혜택은 확정 요구사항이 아니다. 이 초안의 기본정보에 추가하지 않으며 별도 필요성 검토 없이 저장 모델로 옮기지 않는다.
- 월 실적 기준·혜택·실적 인정/제외 규칙은 카드실적 기능의 상세 계약과 함께 결정한다. 시안에 표시된 상품명만으로 자동 확정하지 않는다.
- 카드 실제 사용액·금융사 연동·거래 입력·재활성화·변경 이력은 이번 상세 초안의 신규 기능이 아니다.

## Responsive / Permission

Desktop의 요약·본문·하단 액션은 하나의 상세 카드로 구성한다. Mobile은 같은 내용을 세로로 표시하고 하단 액션이 본문이나 메모를 가리지 않게 한다.

다른 구성원 카드는 읽기 전용이며 수정·비활성화 버튼을 숨긴다. 조회 사용자가 바뀌어도 기존 카드 명의를 자동으로 덮어쓰지 않는다. 이미 비활성인 카드의 기본정보 수정 허용 범위와 재활성화는 미정이다.

## 상태와 예외

Loading, 조회 Error, Not Found, Permission Denied, 비활성화 처리 중, 처리 실패·충돌을 구분한다. 실패한 비활성화를 성공 상태로 표시하지 않는다. 비활성화 이후에도 과거 거래·카드실적의 참조는 유지하고 카드나 관련 이력을 삭제하지 않는다. 외부 연동 장애를 카드 비활성화 상태로 바꾸지 않는다.

## Data / API Dependency

카드 상세, 카드사·유형 표시정보, 로그인 사용자 및 가계 조회/변경 권한, 비활성화 결과가 필요하다. 결제계좌 매핑, 계좌 목록, 활용현황 집계, 카드 상품·혜택 자동조회 API는 필수 의존성이 아니다. endpoint·응답 구조·충돌 정책은 후속 설계에서 확정한다.

## Acceptance Criteria

- [ ] Desktop의 카드 요약과 기본정보가 하나의 상세 카드로 표시된다.
- [ ] 상태 배지 한 곳과 하단 액션만 유지되고 중복 버튼·사용상태 영역이 없다.
- [ ] 카드 명의 설정·결제계좌·활용현황이 없다.
- [ ] 본인 카드와 다른 구성원 카드의 조회/변경 권한이 구분된다.
- [ ] 비활성화 확인·취소·성공·실패·중복 요청을 검증한다.
- [ ] 유효기간·발급일·연회비·혜택 등 미합의 시안 항목을 구현 범위로 자동 확대하지 않는다.
- [ ] 목록 복귀, 마스킹, Desktop/Mobile의 하단 액션 접근성을 검증한다.

위 항목은 이전 전체 제품 초안의 기준이다. 이번 샘플 구현의 동작/검증 범위는 아래 v2 계약과 run별 증적으로 구분하며 전체 제품 완료를 의미하지 않는다.
