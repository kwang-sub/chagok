## 화면 목적

등록된 계좌를 검색·필터링하고, 상세 조회 또는 계좌 등록으로 이동한다. 계좌와 카드는 하나의 상위 메뉴 안에서 탭으로 구분한다. 투자 내역이나 현금 입출금을 입력하는 화면은 아니다.

## Design Reference / Viewport

- 흰 배경, 연한 회색 경계선, 녹색 주요 액션과 민트색 선택·상태 표시를 사용한다.
- Desktop: 공통 사이드바, 제목과 등록 버튼, 계좌/카드 탭, 요약, 검색·필터, 테이블 순서다.
- Mobile: 제목, 계좌/카드 탭, 축약 요약, 검색·필터, 카드형 목록, 등록 진입점을 제공한다.
- 금액·비율은 시안의 샘플 데이터이며 실제 연동 완료나 집계 방식 확정을 뜻하지 않는다. 해상도와 화면별 이미지 분리 규칙은 상위 안내를 따른다.

## 화면 구성

| 영역 | 노출 UI | 설명 |
| --- | --- | --- |
| 제목 | 계좌·카드 정보 관리, 계좌 등록 | 현재 탭에 맞는 등록 버튼을 노출한다. |
| 탭 | 계좌 / 카드 | 계좌를 선택 상태로 표시한다. |
| 요약 | 등록 계좌 수, 사용중/비활성 수 | 집계 대상 가계·구성원 범위를 알 수 있게 한다. 검색 결과 건수와 전체 등록 수는 구분한다. |
| 금액·비율 요약 후보 | 총 잔액, 계좌 유형 비중 | 잔액 출처·기준시점·통화와 유형 분류가 확정된 뒤 제공한다. 미확인 금액을 0으로 만들지 않는다. |
| 필터 | 계좌유형, 금융기관, 구성원, 사용상태 | 구성원 선택은 조회 범위 필터이며 명의 등록·변경 기능이 아니다. |
| 검색 | 계좌명·금융기관 검색 | 번호 검색 범위는 민감정보 정책 확정 전 도입하지 않는다. |
| 목록 | 계좌명, 금융기관, 계좌유형, 마스킹 식별정보, 사용상태 | 가계 전체 조회에서 필요한 명의 정보는 읽기 전용으로 표시할 수 있다. |
| 목록 부가 정보 후보 | 현재 잔액 | 출처가 검증된 조회값만 표시한다. 목록에서 직접 수정하지 않는다. |
| 목록 이동 | 결과 건수, 페이지 이동 | 페이지 크기·정렬 기본값 등은 구현 계약에서 확정한다. |

## 기능 → UI → 사용자 동작 → 결과

| 기능 | 노출 UI / 동작 | 정상 결과 | 조건·예외 |
| --- | --- | --- | --- |
| 카드 목록 전환 | 카드 탭 선택 | [카드 목록](../card-list/screen-spec.md)으로 전환 | 가계 조회 범위는 유지하고 계좌 전용 필터는 카드에 적용하지 않는다. |
| 계좌 등록 | Desktop의 계좌 등록 / Mobile의 등록 버튼 또는 FAB 선택 | [계좌 등록](../account-form/screen-spec.md) 진입 | 명의는 로그인 사용자로 귀속한다. 다른 구성원의 필터를 선택해도 대신 등록하지 않는다. |
| 상세 조회 | 계좌명 또는 목록 항목 선택 | [계좌 상세](../account-detail/screen-spec.md) 진입 | 같은 가계의 조회 허용 범위를 확인한다. 존재하지 않거나 권한이 없으면 상세 데이터를 노출하지 않는다. |
| 검색·필터 | 검색어 입력 또는 조건 변경 | 조건에 맞는 목록과 결과 건수 표시 | 검색 결과 없음과 등록 계좌 자체가 없음을 구분한다. 조건 변경 시 첫 페이지부터 조회하는 방향을 제안한다. |
| 조건 초기화 | 필터 초기화 선택 | 조회 조건을 초기 상태로 복원 | 가계 전환과 필터 초기화를 혼동하지 않게 한다. |
| 재조회 | 새로고침 또는 오류 재시도 선택 | 현재 조건으로 목록을 다시 조회 | 이는 차곡의 목록 재조회이며 금융사 실시간 동기화가 아니다. |
| 페이지 이동 | 이전·다음 또는 페이지 번호 선택 | 검색·필터를 유지한 채 결과 페이지 변경 | 응답 순서가 바뀌어도 이전 요청이 최신 조건의 결과를 덮어쓰지 않도록 후속 구현에서 검증한다. |

목록의 수정 아이콘은 시안 후보로만 남긴다. 기본 편집 진입점은 상세 화면 하단의 수정 버튼이다. 바로가기를 제공하더라도 동일한 본인 권한과 등록/수정 화면을 재사용해야 한다.

## Responsive

Desktop은 비교하기 쉬운 테이블을 사용한다. Mobile은 계좌명·기관·유형·마스킹 정보·상태를 우선하는 카드형 목록을 사용하며 필터는 축약 영역으로 제공할 수 있다. 두 표현의 조회 범위와 권한은 같아야 한다. 등록 진입점은 항상 찾을 수 있게 하되 Mobile에서 상단 추가 버튼과 FAB를 함께 둘지는 중복 동선을 검토한 뒤 확정한다.

## 상태와 권한

| 상태 | 표시와 가능한 행동 |
| --- | --- |
| Loading | 목록을 불러오는 중임을 표시한다. 미확인 건수·잔액을 0으로 표시하지 않는다. |
| Empty | 등록된 계좌가 없다는 안내와 본인 계좌 등록 진입점을 제공한다. |
| No Result | 검색 결과가 없다는 안내와 조건 초기화를 제공한다. 기존 계좌가 삭제된 것으로 표현하지 않는다. |
| Error | 재시도와 입력한 검색·필터 보존을 제공한다. |
| Permission Denied | 조회할 수 없음을 안내하고 허용된 화면으로 돌아가는 경로를 제공한다. |
| 비활성 계좌 | 상태 배지로 구분한다. 과거 참조는 보존하며 신규 거래·투자 선택 대상에서는 제외한다. |

사용자가 다른 구성원 계좌를 조회할 수 있어도 수정·비활성화 권한은 얻지 않는다. 비활성화만을 이유로 자산 총액에서 해당 계좌의 잔액을 무조건 차감하는 규칙은 이 초안에 포함하지 않는다.

## Data / API Dependency

계좌 목록과 상태, 금융기관·계좌유형 기준정보, 가계 조회 권한, 로그인 사용자 정보가 필요하다. 금액 요약은 별도 잔액 조회 계약이 확정될 때 추가한다. 실제 endpoint, 응답 필드, 페이지 크기, 분류 코드는 이 문서에서 확정하지 않는다.

## Acceptance Criteria

- [ ] 계좌/카드 탭과 계좌 등록·상세 진입점이 Desktop/Mobile에서 대응한다.
- [ ] 구성원 필터를 바꿔도 등록 명의는 로그인 사용자를 따른다.
- [ ] 검색·필터·페이지 이동과 상세에서 목록으로 복귀 시의 조건 유지가 검증된다.
- [ ] Empty / No Result / Loading / Error / Permission Denied가 구분된다.
- [ ] 비활성 계좌와 읽기 전용 계좌를 올바르게 구분한다.
- [ ] 결제계좌 연결, 활용현황 집계, 잔액 직접 변경 UI가 없다.

위 항목은 구현 후 검증할 기준이다. 이번 변경은 문서 초안과 이미지 업로드 경로 준비이며 application/browser 검증 완료를 의미하지 않는다.
