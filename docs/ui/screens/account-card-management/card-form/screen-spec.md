# SCR-050-06 카드 등록·수정

Status: DRAFT

마지막 수정: 2026-10-05, KST

상위 명세: [계좌·카드 화면군](../screen-spec.md)

Reference: `./reference.png` — 업로드 예정. 현재 이 폴더에는 설명 초안만 추가한다.

이미지 업로드 방법: [화면별 이미지 안내](../README.md)

## 화면 목적

사용 중인 본인 카드를 등록하거나 기존 카드의 기본정보를 수정한다. 명의는 로그인 사용자로 귀속하므로 입력·선택 UI를 제공하지 않는다. **카드 결제계좌 연결은 제공하지 않으며, 계좌 등록을 카드 등록의 선행 조건으로 두지 않는다.**

## Design Reference / Viewport

흰색·녹색·민트 톤과 기존 입력 컴포넌트 스타일을 따른다. Desktop은 공통 사이드바와 하나의 입력 카드, Mobile은 별도 세로 입력 화면을 사용한다. 주요 액션은 하단 취소·저장이다. 입력 화면 상단에 추가 등록 버튼이나 설정/더보기 버튼을 중복 배치하지 않는다.

등록과 수정은 같은 폼을 재사용하고 제목·초기값·취소 및 저장 후 이동을 구분한다.

## 입력 항목 초안

아래는 화면에서 다룰 후보와 검증 방향이다. 시안의 필수 별표·예시 길이·하이픈 위치를 실제 검증 계약으로 확정하지 않는다.

| 항목 | UI | 초안 및 주의사항 |
| --- | --- | --- |
| 카드명 | 텍스트 입력 | 사용자 구분용 이름. 필수 제안이며 최대 길이·중복 이름 정책은 후속 확정한다. 카드 상품 자동조회 없이 직접 입력하는 초기 방향을 제안한다. |
| 카드사 | 검색 가능한 선택 UI | 검증된 카드사 기준정보에서 선택한다. 필수 제안이며 임의 이름 입력으로 공통 기준정보를 변경하지 않는다. |
| 카드유형 | 신용/체크 등 지원 유형 선택 | 정확한 지원 유형과 코드·필수 여부를 확정한 뒤 적용한다. 시안의 라디오는 표현 방식이다. |
| 카드 식별정보 | 번호 입력 후보 | 형식 검사만 한다. 전체 번호의 필요성·저장 여부·필수 여부·마스킹을 별도 확정한다. |
| 결제일 | 선택 UI 후보 | 날짜 의미·허용 범위·카드유형별 적용 여부·필수 여부는 미정이다. 체크카드에 의미 없는 결제일을 무조건 필수로 요구하지 않는다. |
| 메모 | 여러 줄 입력 | 선택 입력. 최대 길이와 문자수 계산 방식은 후속 확정한다. |
| 사용상태 | 상태 표시/전환 후보 | 신규 카드는 사용중 기본을 제안한다. 상세의 비활성화 확인 흐름을 우회하지 않아야 하며 재활성화는 미정이다. |

명의, 연결계좌, 결제계좌 입력은 없다. 등록 시 인증된 사용자로 소유자를 결정하고 수정 시 기존 소유자를 유지한다. 로그인 사용자가 바뀌었다는 이유로 다른 구성원 카드의 명의를 변경하지 않는다.

유효기간·발급일·연회비·혜택·카드 비밀번호·CVC·인증코드 입력은 이번 폼에 추가하지 않는다. 월 실적 기준과 인정/제외 규칙의 위치는 카드실적 기능과 함께 후속 확정한다.

## 기능 → UI → 사용자 동작 → 결과

| 기능 | 노출 UI / 동작 | 정상 결과 | 조건·예외 |
| --- | --- | --- | --- |
| 등록 진입 | 카드 목록의 카드 등록 | 빈 폼과 카드 등록 제목 표시 | 가계 구성원 필터와 관계없이 로그인 사용자 명의로 등록한다. 계좌가 없어도 진입할 수 있다. |
| 수정 진입 | 카드 상세 하단 수정 | 기존 카드의 수정 가능 정보 표시 | 본인 카드 여부를 확인하고 원본 대신 마스킹값을 그대로 저장하지 않는다. |
| 카드사 검색·선택 | 카드사 검색/선택 | 선택 카드사 반영 | 기관 목록 Loading / No Result / Error를 구분한다. 미등록 기관 처리 방식은 별도 확정한다. |
| 카드유형 선택 | 유형 선택 | 선택한 지원 유형 반영 | 타입 변경 시 결제일·실적 관련 값의 유지/초기화 기준은 후속 확정한다. 미정 값을 임의로 삭제하지 않는다. |
| 번호 형식 확인 | 입력 후 또는 저장 시 | 오류 위치와 수정 안내 | 형식 통과를 카드 실제 존재·명의 인증·결제 가능 확인으로 표시하지 않는다. |
| 저장 | 하단 저장 | 성공한 카드 ID의 [카드 상세](../card-detail/screen-spec.md)로 이동하는 방향을 제안 | 처리 중 중복 제출 방지. 실패 시 입력 보존과 재시도 제공. |
| 취소·뒤로가기 | 하단 취소 / 뒤로가기 | 등록은 [목록](../card-list/screen-spec.md), 수정은 기존 상세로 복귀 | 변경 입력이 있으면 폐기 확인을 제안한다. 저장이나 비활성화를 실행하지 않는다. |

## 번호 입력·중복 검증

허용 문자·길이·공백/하이픈 정규화·검사 알고리즘은 후속 계약에서 확정한다. 이미지의 특정 자리수 또는 자동 하이픈 안내만으로 공통 규칙을 만들지 않는다. 번호 패턴 검사를 통해 실제 발급·명의·사용 가능 여부를 알 수 있다고 표시하지 않는다.

기존 번호의 변경 없이 다른 필드만 수정하는 경우에는 마스킹된 값을 원본으로 재저장하거나 전체 번호 재입력을 무조건 요구하지 않는다. 번호 변경 허용과 원본 보관 정책은 함께 결정한다. 끝자리만으로 전역 중복 여부를 판정하지 않는다. 실제 번호·인증정보를 URL·오류 메시지·로그에 노출하지 않는다.

## 기준정보·저장 실패 상태

| 상태 | 화면 결과 |
| --- | --- |
| 카드사 목록 로딩 | 선택 영역 로딩 표시. |
| 기존 검증 목록 사용 | 외부 갱신 실패 시 기존 목록·선택·참조를 보존하고 필요 시 안내. 기준년월과 수집시각 구분. |
| 초기 목록 없음 | 조회 재시도와 안내. 카드사가 필수로 확정되면 목록 확보 전 저장 제한. |
| 필드 오류 | 오류 필드와 이유를 표시하고 다른 입력 보존. |
| 중복·동시 수정 충돌 | 기존 카드 또는 최신 상태를 확인하도록 안내. 임의 덮어쓰기·중복 생성 방지 방식은 후속 계약으로 확정. |
| 저장 실패 | 입력을 보존하고 재시도 제공. 성공 여부가 불명확하면 확인 없이 카드 생성 요청을 반복하지 않도록 설계. |
| 권한 상실 | 변경을 차단하고 접근 제한 안내. |

## Responsive / Data Dependency

Desktop/Mobile의 입력·권한·검증은 동일하다. Mobile에서 긴 메모와 오류 메시지가 저장 버튼에 가려지지 않도록 하며 키보드 탐색과 필드 라벨 연결을 고려한다.

카드 생성·수정·상세 읽기, 카드사·카드유형 기준정보, 로그인 사용자 권한이 필요하다. 계좌 목록·결제계좌 매핑·금융사 실시간 거래·활용현황 집계 API는 필요하지 않다. 실제 endpoint, 필수 항목, 번호 저장·중복·충돌 정책은 구현 전 확정한다.

## Acceptance Criteria

- [ ] 등록·수정 모드의 제목·초기값·취소/저장 결과가 구분된다.
- [ ] 명의 입력·선택이 없고 서버에서 본인 소유권을 검증한다.
- [ ] 계좌가 없어도 카드 등록이 가능하며 결제계좌 입력·매핑 요청이 없다.
- [ ] 카드사 검색의 로딩·검색 결과 없음·오류·기존 목록 사용을 구분한다.
- [ ] 번호의 형식 확인과 실제 카드 인증을 구분하고 마스킹값을 재저장하지 않는다.
- [ ] 실패·충돌 시 입력 보존과 중복 제출 방지가 동작한다.
- [ ] 카드 등록·수정이 거래·청구·현금잔고를 생성하거나 변경하지 않는다.

위 항목은 구현 후 검증할 기준이며 이번 변경은 문서 초안과 이미지 업로드 경로 준비에 한정한다.
