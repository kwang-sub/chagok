# SCR-022 투자 내역

Status: APPROVED

Reference: `./reference.png`

Legacy detail: `docs/product/screens/SCR-022-investment-history.md`

## Design Reference

승인 기준 이미지는 **투자금 투입 이력 중심의 투자 내역 최종 시안**이다.

핵심 시각 요소:
- 전체 / 정기 투자 / 추가 납입 / 일시 투자 탭
- 총 투자금 / 완료 금액 / 진행 중 금액 / 보류 금액 / 건너뛰기 금액 요약
- 기간 / 유형 / 계좌 / 상태 / 키워드 필터
- 투자 내역 테이블
- 상세 Drawer
- 다시 투자하기 / 복사하여 새로 등록
- 매수/매도 제안과 실제 실행 결과 비교
- Mobile 투자 내역, 상세, 투자하기 진입, 매수/매도 제안

## Viewport

- Desktop: reference의 PC 리스트/Drawer 기준
- Mobile: reference의 각 Mobile 프레임 기준

## 화면 목적

정기 투자, 추가 납입, 일시 투자 등 투자금 투입의 전체 이력과 각 투자 실행 상태 및 결과를 조회한다.

## 주요 상태

- 진행
- 보류
- 건너뛰기
- 완료
- loading
- empty
- error

## Responsive

- Desktop: 요약 KPI + 필터 + 테이블 + 상세 Drawer
- Mobile: 요약 카드 + 간결한 리스트 + 별도 상세/실행 화면

## Interaction

- 기간/유형/계좌/상태/키워드 필터
- 투자 내역 상세 조회
- 동일 조건 다시 투자하기
- 기존 투자금을 복사하여 새 투자금 등록
- 매수/매도 제안과 실제 실행 결과 비교

## Data / API Dependency

초기 구현에서 본 화면은 실제 데이터 연결 대상이다.

- investment funding history
- investment execution status
- suggestion snapshots
- execution results
- account metadata

## Acceptance Criteria

- 종목별 체결 장부가 아니라 Investment Funding/Execution 이력을 중심으로 구성한다.
- 정기/추가/일시 투자 유형을 동일한 목록에서 구분 가능해야 한다.
- 제안 결과와 실제 실행 결과를 함께 확인할 수 있어야 한다.
- 완료/보류/건너뛰기 상태를 명확하게 구분한다.
- PC/Mobile과 상세 Drawer/실행 흐름을 Design Conformance 검증한다.

## v2 문서 범위와 근거

기존 설명·디자인 승인과 경로는 유지한다. 동작은 DRAFT이며 CONFIRMED는 기존 문서에 명시된 규칙의 재사용만 뜻한다. 상세의 제안/미확정까지 승인하지 않는다.
`제품 §번호`는 `docs/product/screens/SCR-022-investment-history.md`의 항목이다. 소스나 이미지를 새로 분석하지 않았다.
VISUAL은 기존 Design Reference/Acceptance Criteria의 시각 계층·시안 일치 목표를 정규화한다. 정확한 viewport는 UNKNOWN이다.
기존 탭/필터/요약/목록은 F-01/F-02, 상세/결과 비교는 F-03, 다시 투자하기는 F-04, 실행 진입은 F-05로 연결한다. `복사하여 새로 등록`은 아래 범위 충돌 항목이며 구현 범위로 확정하지 않는다.

## 미확정 사항 및 문서 충돌

- 범위 외/결정 대기: 기존 Design Reference/Interaction의 `복사하여 새로 등록`은 제품 §7의 향후 기능과 충돌한다. 이번 제공 여부 UNKNOWN이며 F-04와 같은 버튼이라고 합치거나 구현 대상으로 승격하지 않는다. 별도 노출/복사/확인/생성 시점을 결정해야 한다.
- F-02: 필터 기본값·적용·초기화·연속 변경 정책을 결정해야 한다. 제품 §10에는 명의 필터가 있지만 기존 UI 명세에는 없다. 포함 여부 UNKNOWN이다.
- F-03: 제품 §6은 실제 반영금액/수량을 선택이라고 하나 §19는 필수 여부 추후 확정이다. 최종 입력 정책을 결정해야 하며 조회 화면에서 필수로 강제하지 않는다.
- F-04: 제품 §7의 복사 개요와 §19의 복사 범위 미확정을 함께 유지한다. 생성 시점·확인/취소·중복 실패 복구는 새 결정 필요.
- F-01/F-03: 비활성 기본 제외, 페이지 이동/동률 정렬, 상세 복귀 상태·포커스·실패 재시도는 미확정이다. 비활성화 동작 UI 자체는 이 문서 범위로 새로 추가하지 않는다.
- F-05: 대기 상태 enum 대응·조회 전용 액션 표현은 미확정이며 포트폴리오의 상태별 결정표와 일치시켜야 한다.
- 구조 검사는 기능 성공/승인/Design Conformance를 뜻하지 않는다. Node/JVM/browser 검증은 문서 작업 범위로 NOT_REQUIRED/NOT_RUN이다.
