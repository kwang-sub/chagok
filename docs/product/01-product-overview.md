# 차곡 제품 개요

> 상태: 초안(Draft)
> 기준 요구사항: `우리자산관리.xlsx`
> 문서 목적: 차곡의 제품 방향과 1차 개발 범위를 정의한다.

## 1. 제품 목적

차곡은 현재 스프레드시트로 관리하고 있는 가계 자산관리 체계를 웹 애플리케이션으로 전환하는 것을 목표로 한다.

단순 투자 포트폴리오 관리에 한정하지 않고 다음 정보를 하나의 흐름으로 연결한다.

- 금융자산
- 투자자산
- 부채
- 수입
- 지출
- 카드 사용 및 실적
- 정기 현금흐름
- 순자산 추이

핵심 목표는 `현재 재무상태를 파악하고, 돈이 어디에서 들어와 어디로 이동했는지 확인하며, 투자와 소비 의사결정에 필요한 정보를 한곳에서 제공하는 것`이다.

## 2. 제품 원칙

### 2.1 가계 단위 관리

차곡의 최상위 관리 단위는 개인 계좌가 아니라 가계(Household)로 정의한다.

- 가계 전체 자산/부채/수입/지출 조회
- 구성원별 자산 및 거래 조회
- 공동 자산과 개인 자산을 함께 관리할 수 있는 구조

구성원, 공동자산의 상세 정책은 화면 설계 단계에서 확정한다.

### 2.2 기존 엑셀 기능을 요구사항 원본으로 사용

`우리자산관리.xlsx`에서 이미 사용 중인 계산 방식과 업무 흐름을 우선 분석한다.

엑셀 시트를 화면과 DB 테이블로 그대로 복제하지 않고 다음 순서로 재설계한다.

```text
기존 엑셀 기능
→ 사용자 기능
→ 화면
→ 업무 규칙
→ 도메인/DB
→ API
```

### 2.3 기능 명세와 화면 설계 분리

- GitHub Markdown: 기능, 업무 규칙, 화면 명세의 기준 문서
- Figma: 화면 배치 및 UX 기준
- GitHub Issue/PR: 개발 작업과 변경 이력

화면은 `SCR-xxx`, 기능은 `FTR-xxx` 식별자를 사용해 문서·Figma·개발 작업을 연결한다.

## 3. 대상 사용자

1차 버전은 개인 또는 부부/가구가 직접 자신의 재무정보를 관리하는 사용자를 대상으로 한다.

주요 사용 목적:

- 현재 총자산/순자산 확인
- 금융자산과 투자자산 현황 확인
- ETF 등 투자 포트폴리오 관리
- 월별 수입과 지출 흐름 확인
- 카드 거래 및 카드 실적 관리
- 정기지출/정기투자 관리
- 부채 잔액 및 상환 현황 관리
- 월별 순자산 변화 추적

## 4. 1차 핵심 기능 범위

### 4.1 홈

- 총자산
- 총부채
- 순자산
- 투자 평가금액
- 이번 달 수입/지출
- 월 현금흐름 요약
- 순자산 추이 요약

### 4.2 자산관리

- 금융자산 등록/수정/조회
- 구성원/자산유형별 조회
- 부채 등록/수정/조회
- 순자산 계산 및 월별 추이

### 4.3 투자관리

- 투자계좌 관리
- 국내 ETF 검색
- 보유 종목/수량/매입정보 관리
- 현재 평가금액 및 수익률 계산
- 목표비중/현재비중 비교
- 투자 입금 및 투자내역 관리

### 4.4 지출관리

- 카드 거래내역 조회
- 카테고리 분류
- 거래 반영/제외
- 중복거래 검사
- 월별 지출 분석
- 카드 실적 및 부족금액 확인
- 정기지출 관리

### 4.5 수입 및 현금흐름

- 급여/상여/기타수입 등록
- 정기 현금흐름 관리
- 수입 대비 소비/저축/투자 비율 확인

### 4.6 데이터 가져오기

1차 버전에서는 금융사 직접 연동보다 파일 가져오기를 우선한다.

- 카드사 XLSX/CSV 가져오기
- 컬럼 매핑
- 카드/명의 매핑
- 중복검사
- 가져오기 결과 확인

세부 지원 파일 형식과 카드사는 추후 확정한다.

## 5. 현재 완료된 PoC

국내 ETF 시세 연동 가능성을 검증했다.

- 금융위원회 공공데이터 API를 통한 최신 기준일 ETF 조회
- Google Sheets + `GOOGLEFINANCE`를 통한 선택 ETF 가격 조회
- Google Sheets API를 통한 계산 결과 회수
- 여러 ETF의 Sheet 행 관리
- 가격 지연시간 및 거래시간 확인

PoC 코드는 실제 서비스 구현 시 Provider 추상화 및 저장 구조를 다시 설계한다.

## 6. 1차 범위에서 제외하거나 추후 결정할 항목

- 은행/증권사 Open API 자동 계좌연동
- 카드사 실시간 API 연동
- 자동 결제/이체 기능
- Kafka 등 이벤트 스트리밍 도입
- 고도화된 투자 추천
- 세금 신고/절세 자동화
- 다가구/상용 멀티테넌시

필요성이 확인될 때 별도 요구사항으로 추가한다.

## 7. 개발 전 산출물 순서

```text
제품 개요
→ 전체 화면 구성도
→ 화면별 기능 명세
→ Figma 화면 초안
→ 기능 요구사항/업무 규칙 확정
→ 도메인 모델
→ DB 설계
→ API 설계
→ 개발 작업 분해
→ 구현
```

## 8. 문서 상태 기준

- `초안`: 대화 및 화면 설계 과정에서 변경 가능
- `검토`: 구현 전 정책 검토 중
- `확정`: 개발 기준으로 사용
- `변경`: 확정 후 요구사항 변경이 발생한 상태
