# SCR-011 부채 관리

> 상태: 화면 구성 확정
> 상위 문서: `docs/product/03-screen-specification.md`
> 디자인 기준: 확정된 PC/Mobile 부채 관리 시안

## 1. 화면 목적

가계가 보유한 부채 현황을 한눈에 확인하고, 구성원별 대출·차입금 등의 상세정보와 남은 원금, 월 상환 부담, 금리, 만기 정보를 관리한다.

홈 대시보드의 `총부채`, 순자산 계산 및 향후 월간 보고서의 부채 관련 지표는 본 화면의 데이터를 기준으로 한다.

## 2. 화면 설계 원칙

- Mobile First로 설계한다.
- PC는 여러 부채를 비교·관리하기 쉽도록 테이블 중심 UI를 사용한다.
- Mobile은 핵심 상환정보를 빠르게 확인할 수 있도록 카드/목록 중심 UI를 사용한다.
- 상단에서는 총부채, 이번 달 상환액, 월 이자 부담을 우선 노출한다.
- 같은 가계 구성원의 부채는 조회할 수 있으나 등록·수정·비활성화는 해당 부채의 당사자만 수행할 수 있다.
- 부채는 물리 삭제하지 않는다.
- `완납`과 `비활성화`를 서로 다른 상태로 관리한다.
- 금액은 저장·계산 과정에서 임의 반올림하지 않는다.

## 3. 시안 데이터 및 가명 사용 원칙

화면 명세, 와이어프레임, Figma 및 개발 전 시안에서 사용하는 사람 이름·가계명·부채명·금융기관명 등은 모두 예시용 가명 또는 샘플 데이터로 사용한다.

예시:

```text
구성원: 민준, 서연
가계: 민준·서연 가계
부채명: 주택담보대출, 생활안정대출, 전세보증금대출
금융기관: 샘플은행, 샘플저축은행
```

- 실제 사용자의 개인정보 또는 실제 금융정보를 시안에 고정값으로 사용하지 않는다.
- 실제 구현에서는 해당 표시값을 DB 또는 API 조회 결과로 치환한다.
- 문서의 샘플 값은 화면 구조와 데이터 관계를 설명하기 위한 예시이며 비즈니스 규칙으로 간주하지 않는다.

## 4. 조회 범위

화면 상단에서 조회 대상을 전환할 수 있다.

```text
가계 전체 / 구성원 A / 구성원 B / ...
```

- 기본값은 `가계 전체`로 한다.
- 같은 가계에 소속된 구성원만 선택할 수 있다.
- `가계 전체` 선택 시 가계 구성원의 활성 부채 및 상환중 부채를 조회한다.
- 특정 구성원 선택 시 해당 구성원 명의 부채만 조회한다.
- 같은 가계 구성원은 다른 구성원의 상세 부채정보를 조회할 수 있다.
- 다른 구성원 소유 부채의 수정/비활성화 동작은 노출하지 않는다.

## 5. 상태 정책

부채 상태는 최소 다음을 구분한다.

| 상태 | 설명 | 현재 총부채 집계 |
| --- | --- | --- |
| 상환중 | 현재 원금 또는 이자 상환이 진행 중인 부채 | 포함 |
| 완납 | 원금과 필요한 이자 상환이 완료된 부채 | 제외 |
| 비활성화 | 잘못 등록했거나 관리 대상에서 제외한 부채 | 제외 |

### 5.1 완납

- 실제 상환이 종료된 정상적인 재무 이력이다.
- 완납일을 보존한다.
- 과거 보고서 및 이력에서 조회할 수 있어야 한다.
- 완납 처리 시 현재 총부채에서는 제외한다.

### 5.2 비활성화

- 잘못 등록했거나 더 이상 차곡에서 관리하지 않는 데이터를 의미한다.
- 물리 삭제 대신 사용한다.
- 기존 참조 및 과거 이력은 유지한다.
- 일반 조회의 기본 목록에서는 제외한다.

`완납`과 `비활성화`는 동일하게 처리하지 않는다.

## 6. PC 화면 구성

```text
┌──────────────┬──────────────────────────────────────────────────────────────┐
│ 차곡          │ 부채 관리                                      [+ 부채 등록]│
│              │ [민준·서연 가계 ▼]                                        │
│ 홈           ├──────────────────────────────────────────────────────────────┤
│ 자산          │ [총 부채]       [이번 달 상환액]       [월 이자 부담]       │
│ 부채          ├──────────────────────────────┬───────────────────────────────┤
│ 투자          │ 부채 구성                    │ 부채 추이                     │
│ 지출          │ [Donut / Legend]             │ [Line Chart]                  │
│ 현금흐름      ├──────────────────────────────────────────────────────────────┤
│ 보고서        │ [구성원 ▼] [부채유형 ▼] [금융기관 ▼] [상태 ▼] [검색]       │
│ 설정          ├──────────────────────────────────────────────────────────────┤
│              │ 부채명 | 명의 | 유형 | 금융기관 | 남은원금 | 금리 | 월상환액 │
│              │ ---------------------------------------------------------- │
│              │ 주택담보대출 | 민준 | 주택담보 | 샘플은행 | ...             │
│              │ 생활안정대출 | 서연 | 신용     | 샘플은행 | ...             │
│              └──────────────────────────────────────────────────────────────┘
└──────────────┴──────────────────────────────────────────────────────────────┘
```

PC에서는 부채 목록을 테이블로 제공하고, 행 선택 시 상세 Drawer를 연다.

## 8. 영역별 상세 명세

### 8.1 상단 요약

표시 정보:

- 총 부채
- 전월 대비 총부채 증감 금액
- 전월 대비 총부채 증감률
- 이번 달 상환액
- 월 이자 부담

`이번 달 상환액`은 해당 월에 실제 또는 예정된 원금+이자 상환액의 합계를 의미한다. 실제 계산 기준은 상환 데이터 모델 설계 시 최종 확정한다.

`월 이자 부담`은 현재 관리 중인 부채의 해당 월 이자 합계를 의미한다.

### 8.2 부채 구성

부채 유형별 현재 남은 원금을 기준으로 비중을 표시한다.

예시 유형:

```text
주택담보 / 신용 / 전세·보증금 / 학자금 / 자동차 / 기타
```

PC는 Donut Chart + Legend를 기본으로 한다. Mobile은 동일 데이터를 축약된 Donut 또는 유형별 요약 목록으로 표현할 수 있다.

### 8.3 부채 추이

표시 정보:

- 기간별 총 부채 잔액 변화
- 기준일 또는 기준월

PC에서는 Line Chart를 기본으로 한다.

Mobile에서는 초기 화면의 정보량을 고려하여 부채 추이를 생략하거나 요약형으로 제공할 수 있다.

부채 추이의 기본 조회기간 및 스냅샷 생성 기준은 순자산 추이 정책과 함께 확정한다.

### 8.4 검색 및 필터

지원 후보:

- 구성원
- 부채유형
- 금융기관/채권자
- 상태
- 부채명 검색
- 정렬

기본 상태 필터는 `상환중`을 우선한다.

정렬 후보:

- 남은 원금 높은 순
- 월 상환액 높은 순
- 금리 높은 순
- 만기 가까운 순
- 최근 등록/수정 순

## 9. PC 부채 목록

후보 컬럼:

- 부채명

- 금융기관/채권자

## 11. 부채 상세

### 11.1 PC

PC에서는 목록 행 선택 시 우측 Drawer를 연다.

기본 표시 후보:

- 부채명
- 상태
- 명의
- 부채유형
- 금융기관/채권자
- 최초 대출금액
- 현재 남은 원금
- 현재 금리
- 금리 유형
- 상환방식
- 월 상환액
- 실행일
- 만기일
- 완납일
- 메모
- 최종 수정일시

본인 소유 부채라면:

- 수정
- 완납 처리
- 비활성화

다른 구성원의 부채라면:

- 조회만 가능
- 수정/완납/비활성화 버튼 미노출

### 11.2 Mobile

Mobile에서는 별도 상세 화면을 사용한다.

PC Drawer의 핵심 정보를 세로로 배치하고 본인 소유 부채에 대해서만 관리 버튼을 제공한다.

## 12. 부채 등록/수정

### 12.1 PC

일반적인 부채 등록/수정은 Modal을 기본으로 한다.

입력 항목이 길어지거나 향후 상환계획/금리변경 이력 등 복잡한 기능이 추가되면 별도 화면 전환을 검토한다.

### 12.2 Mobile

등록/수정은 별도 화면으로 제공한다.

### 12.3 공통 입력항목 후보

- 부채명
- 명의
- 부채유형
- 금융기관/채권자
- 최초 대출금액
- 현재 남은 원금
- 현재 금리
- 금리 유형
- 상환방식
- 월 상환액
- 실행일
- 만기일
- 메모

`명의`는 현재 로그인 사용자를 기본값으로 하며 일반 사용자가 다른 구성원 명의의 부채를 대신 등록할 수 없도록 한다.

## 13. 부채유형 및 상환방식

### 13.1 부채유형

부채유형은 시스템 공통 기준정보로 관리한다.

예시:

```text
주택담보대출
신용대출
전세·보증금대출
학자금대출
자동차대출
개인차입금
기타
```

일반 사용자와 가계 대표자는 활성화된 부채유형을 선택만 할 수 있다.

### 13.2 상환방식

초기 지원 후보:

```text
원리금균등
원금균등
만기일시
기타
```

상환방식은 대출 스케줄 계산 기능과 분리하여 관리한다.

초기 버전에서는 상환방식과 현재 월 상환액을 저장하고, 모든 미래 상환 스케줄을 자동 계산하는 기능은 필수 범위에서 제외한다.

## 14. 금리 정책

초기 화면에서는 현재 적용 금리를 관리한다.

후속 기능 후보:

- 고정금리 / 변동금리 구분
- 금리 변경 이력
- 기준금리/가산금리 분리
- 향후 이자 자동 계산

초기 구현에서는 과도한 대출계산 엔진을 만들지 않고 `현재 금리 + 현재 월 상환액` 중심으로 관리하는 것을 기본으로 한다.

## 15. 완납 처리

본인 소유의 `상환중` 부채에 대해 완납 처리를 제공한다.

완납 시:

- 상태를 `완납`으로 변경
- 남은 원금을 `0`으로 처리하는 정책을 기본 후보로 한다.
- 완납일 저장
- 현재 총부채 집계에서 제외
- 과거 부채 이력 및 보고서에서는 유지

남은 원금과 완납 처리 간 검증 규칙은 도메인 설계 시 확정한다.

## 16. 비활성화 정책

- 부채 물리 삭제 기능은 제공하지 않는다.
- 잘못 등록했거나 관리 대상에서 제외하는 경우 비활성화한다.
- 비활성화 데이터는 기본 현재 부채 목록과 총부채 집계에서 제외한다.
- 과거 참조 데이터와 감사/변경 이력은 유지한다.
- 비활성화는 해당 부채의 당사자만 수행할 수 있다.

## 17. 데이터 상태

### Empty

```text
등록된 부채가 없습니다.
부채가 있다면 등록하여 순자산을 정확하게 관리해보세요.
[부채 등록]
```

### No Result

```text
조건에 맞는 부채가 없습니다.
필터 또는 검색 조건을 변경해보세요.
[필터 초기화]
```

### Loading

- 요약 영역: Skeleton Card
- 차트: Skeleton Chart
- PC 목록: Skeleton Row
- Mobile 목록: Skeleton Card

### Error

- 전체 화면을 불필요하게 차단하지 않는다.
- 실패한 영역 단위로 오류 메시지 및 재시도 버튼을 제공한다.

### Permission Denied

현재 가계에 대한 조회 권한이 없는 경우 부채 정보를 노출하지 않는다.

## 18. 금액 및 비율 표시

- 원화 금액은 천 단위 구분자를 적용한다.
- 예: `55,000,000원`
- 금액 저장·계산에는 `BigDecimal`, DB에는 `DECIMAL/NUMERIC` 계열 사용 원칙을 따른다.
- 원금, 이자 등 금융 금액은 임의 반올림하지 않는다.
- 금리 UI는 `%`로 표시한다.
- 표시 소수점 자릿수는 UI 정책으로 관리하되 원본 금리값의 정밀도는 변경하지 않는다.

## 19. 권한 정책

- 가계는 데이터 접근 경계다.
- 같은 가계 구성원은 가계 전체 및 개별 구성원의 부채 상세를 조회할 수 있다.
- 등록은 본인 명의 부채만 가능하다.
- 수정/완납/비활성화는 해당 부채의 명의자만 가능하다.
- 시스템 관리자 권한과 가계 대표자 권한은 별개다.
- 부채유형과 시스템 기준정보의 관리는 시스템 관리자만 수행한다.

```text
SCR-011 부채 상세 / Mobile

```

확정된 시안의 디자인 언어를 기준으로 한다.

- PC: 상단 요약 + 부채 구성/추이 + 필터 + 테이블
- Mobile: 상단 핵심 지표 + 부채 구성 + 필터 + 카드 목록
- PC 상세: Drawer
- PC 등록/수정: Modal
- Mobile 상세/등록/수정: 별도 화면
- 차곡 공통의 밝은 배경, 얇은 경계선, 절제된 그림자와 녹색 포인트 사용
- 시안의 이름과 금융정보는 모두 가명/샘플 데이터 사용

## 21. 확정 및 추후 항목

### 확정

- 확정된 PC/Mobile 시안을 `SCR-011` 기준 디자인으로 사용
- 총 부채 / 이번 달 상환액 / 월 이자 부담을 핵심 KPI로 노출
- PC 부채 목록은 테이블 중심
- Mobile 부채 목록은 카드 중심
- PC 상세는 Drawer
- PC 일반 등록/수정은 Modal
- Mobile 상세/등록/수정은 별도 화면
- 같은 가계 구성원 간 상세 조회 허용
- 등록/수정/완납/비활성화는 해당 부채 명의자만 허용
- 물리 삭제하지 않음
- `상환중`, `완납`, `비활성화` 상태를 구분
- 완납은 정상 재무 이력으로 보존
- 초기 버전에서는 현재 금리와 현재 월 상환액 중심으로 관리
- 시안/문서 샘플은 가명 사용, 실제 구현에서는 DB/API 값을 사용
