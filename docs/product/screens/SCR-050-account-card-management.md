# SCR-050 계좌·카드 정보 관리

> 상태: 1차 화면 명세(Draft)
> 상위 문서: `docs/product/03-screen-specification.md`
> 통합 대상: 기존 `SCR-021 투자 계좌`, `SCR-091 카드 설정`

## 1. 화면 목적

사용자가 차곡에서 사용하는 계좌와 카드를 한곳에서 등록·조회·수정·비활성화하고, 투자·거래·카드실적 등 다른 기능에서 참조할 금융수단 정보를 관리한다.

본 화면은 거래나 투자 성과를 분석하는 화면이 아니라 `어떤 금융수단을 사용하고 있는가`를 관리하는 기준 화면이다.

## 2. 기본 구조

```text
계좌·카드 정보 관리

[ 계좌 ] [ 카드 ]
```

계좌와 카드는 하나의 화면에서 탭으로 전환한다.

### 계좌

- 은행계좌
- 증권계좌
- 연금계좌
- 기타계좌

### 카드

- 신용카드
- 체크카드
- 기타 결제수단

정확한 유형은 시스템 관리자 기준정보를 사용한다.

## 3. 권한

- 같은 가계 구성원의 계좌·카드 정보는 조회할 수 있다.
- 등록·수정·비활성화는 해당 금융수단의 당사자만 수행할 수 있다.
- 일반 사용자는 다른 구성원의 계좌·카드를 대신 등록할 수 없다.
- 계좌유형·카드유형 등 시스템 공통 기준정보는 시스템 관리자만 관리한다.
- 물리 삭제하지 않고 비활성화 정책을 적용한다.

## 4. PC 화면 구조

```text
계좌·카드 정보 관리                         [+ 계좌 등록]
[가계 전체 ▼]

[ 계좌 ] [ 카드 ]

[전체] [은행] [증권] [연금] [기타]     [검색] [필터]

계좌명       명의   금융기관   계좌유형   연결정보       상태
------------------------------------------------------------
생활비 통장   민준   샘플은행   입출금     자산/현금흐름   사용중
투자 계좌     민준   샘플증권   증권       투자           사용중
연금 계좌     서연   샘플증권   연금       자산           사용중
```

카드 탭:

```text
[ 계좌 ] [ 카드 ]                           [+ 카드 등록]

[전체] [신용] [체크] [기타]           [검색] [필터]

카드명       명의   카드사     카드유형   결제계좌     실적기준   상태
-------------------------------------------------------------------
생활 카드     민준   샘플카드   신용       생활비 통장   500,000   사용중
교통 카드     서연   샘플카드   체크       주거래 통장   -         사용중
```

PC는 테이블 중심으로 구성하며 행 선택 시 상세 Drawer를 제공한다.

```text
← 계좌·카드 정보 관리        +
[가계 전체 ▼]

[ 계좌 ] [ 카드 ]

[전체 ▼]          [검색] [필터]

생활비 통장
민준 · 샘플은행 · 입출금
자산/현금흐름 연결          >

투자 계좌
민준 · 샘플증권 · 증권
투자 포트폴리오 연결       >

연금 계좌
서연 · 샘플증권 · 연금      >
```

카드 탭에서는 동일한 카드형 목록 패턴을 사용한다.

Mobile 상세·등록·수정은 별도 화면으로 제공한다.

## 6. 계좌 정보

### 공통 입력 후보

- 계좌명
- 명의
- 금융기관
- 계좌유형
- 계좌 식별정보
- 개설일(선택)
- 메모

### 증권/투자계좌 연결

증권계좌는 다음 기능에서 참조할 수 있다.

```text
SCR-050 계좌
→ SCR-020 투자 포트폴리오
→ SCR-022 투자 내역
```

포트폴리오와 투자내역 화면에서는 계좌를 새로 생성하지 않고 `SCR-050`에 등록된 활성 계좌를 선택한다.

### 자산과의 관계

계좌 자체와 계좌에 존재하는 자산 잔액/투자자산을 동일 개념으로 취급하지 않는다. 정확한 Aggregate 및 소유관계는 도메인 모델링 단계에서 결정한다.

## 7. 카드 정보

### 공통 입력 후보

- 카드명
- 명의
- 카드사
- 카드유형
- 결제계좌
- 결제일
- 월 실적 기준
- 메모

### 거래/실적 연결

```text
SCR-050 카드
├─ SCR-031 거래 내역
└─ SCR-032 카드 실적
```

카드 거래 가져오기에서도 `SCR-050`에 등록된 카드와 매핑한다.

카드별 실적 인정/제외 규칙의 상세 모델은 `SCR-032 카드 실적` 및 도메인 설계 단계에서 확정한다.

## 8. 상세 화면

### PC

행 선택 시 우측 Drawer를 제공한다.

본인 금융수단:

- 조회
- 수정
- 비활성화

다른 구성원 금융수단:

- 조회만 가능

### Mobile

별도 상세 화면을 사용한다.

## 9. 등록/수정

### PC

일반적인 계좌·카드 등록/수정은 Modal을 기본으로 한다.

### Mobile

별도 등록/수정 화면을 사용한다.

`명의`는 로그인 사용자를 기본값으로 하며 일반 사용자가 다른 구성원으로 변경할 수 없도록 한다.

## 10. 비활성화

- 계좌·카드를 물리 삭제하지 않는다.
- 사용 종료 시 비활성화한다.
- 비활성화된 금융수단은 신규 거래·투자 입력 시 선택할 수 없다.
- 과거 거래, 투자내역, 카드실적에서 사용된 정보는 유지한다.
- 과거 데이터 조회 시 당시 사용한 계좌·카드명을 확인할 수 있어야 한다.
- 재활성화 정책은 추후 확정한다.

## 11. 검색 및 필터

계좌:

- 구성원
- 금융기관
- 계좌유형
- 사용상태
- 계좌명 검색

카드:

- 구성원
- 카드사
- 카드유형
- 사용상태
- 카드명 검색

## 12. 데이터 상태

공통 화면 정책의 다음 상태를 제공한다.

- Empty
- No Result
- Loading
- Error
- Permission Denied

Empty 예시:

```text
등록된 계좌가 없습니다.
차곡에서 사용할 계좌를 등록해보세요.
[계좌 등록]
```

카드 탭에서도 동일한 패턴을 적용한다.

## 13. 가명/샘플 데이터

문서, 시안, Figma에서는 모든 이름·금융기관·계좌·카드 정보를 가명 또는 샘플값으로 사용한다.

실제 구현에서는 DB/API 조회 결과를 사용한다.

## 15. 추후 확정

- 계좌번호 등 민감한 식별정보의 저장/마스킹 범위
- 계좌와 자산 Aggregate의 정확한 관계
- 체크카드의 카드실적 적용 여부
- 카드별 실적 인정/제외 규칙 모델
- 결제계좌 변경 이력 보존 여부
- 비활성 금융수단 재활성화 정책
- PC 사이드바에서 본 화면의 최종 진입 위치
