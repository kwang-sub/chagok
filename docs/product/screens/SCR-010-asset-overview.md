# SCR-010 자산 현황

> 상태: 화면 구성 확정
> 상위 문서: `docs/product/03-screen-specification.md`
> 디자인 기준: 확정된 두 번째 자산 현황 PC/Mobile 시안

## 1. 화면 목적

가계가 보유한 금융자산과 기타 관리대상 자산을 한 화면에서 조회하고, 자산 유형·구성원·금융기관 등 기준으로 탐색할 수 있도록 한다.

자산 현황 화면은 단순 총액 확인뿐 아니라 개별 자산을 찾고 상세정보를 조회하거나 본인 자산을 등록·수정·비활성화하는 관리 화면으로 사용한다.

## 2. 화면 설계 원칙

- Mobile First로 설계한다.
- PC는 많은 자산을 비교·관리하기 쉽도록 테이블 중심 UI를 사용한다.
- Mobile은 한 손 탐색과 가독성을 고려하여 카드/목록 중심 UI를 사용한다.
- 자산 전체 규모와 자산 유형별 구성을 상단에서 요약한다.
- 동일 가계 구성원의 자산은 조회할 수 있으나 등록·수정·비활성화는 해당 자산의 당사자만 수행할 수 있다.
- 자산 삭제는 제공하지 않고 비활성화 정책을 적용한다.
- 자산유형은 시스템 관리자 기준정보를 사용하며 일반 사용자가 임의 생성하지 않는다.
- 금액은 저장·계산 과정에서 반올림하지 않는다.

## 3. 시안 데이터 및 가명 사용 원칙

화면 명세, 와이어프레임, Figma 및 개발 전 시안에서 사용하는 사람 이름·가계명·자산명·금융기관명·계좌명 등은 모두 예시용 가명 또는 샘플 데이터로 사용한다.

예시:

```text
구성원: 민준, 서연
가계: 민준·서연 가계
자산명: 생활비 통장, 주거래 예금, 장기 적금
금융기관: 샘플은행, 샘플증권
```

- 실제 사용자의 개인정보 또는 실제 금융정보를 시안에 고정값으로 사용하지 않는다.
- 실제 구현에서는 해당 표시값을 DB 또는 API 조회 결과로 치환한다.
- 문서의 샘플 값은 데이터 모델의 구조와 화면 동작을 설명하기 위한 값일 뿐 비즈니스 규칙으로 간주하지 않는다.

## 4. 조회 범위

화면 상단에서 조회 대상을 전환할 수 있다.

```text
가계 전체 / 구성원 A / 구성원 B / ...
```

- 기본값은 `가계 전체`로 한다.
- 같은 가계에 소속된 구성원만 선택할 수 있다.
- `가계 전체` 선택 시 모든 구성원의 활성 자산을 조회한다.
- 특정 구성원 선택 시 해당 구성원 소유 자산만 조회한다.
- 다른 가계 또는 소속되지 않은 사용자의 자산은 조회할 수 없다.
- 다른 구성원의 자산 상세는 조회할 수 있으나 수정/비활성화 동작은 노출하지 않는다.

## 5. PC 화면 구성

```text
┌──────────────┬──────────────────────────────────────────────────────────────┐
│ 차곡          │ 자산 현황                                      [자산 등록] │
│              │ [민준·서연 가계 ▼]                                        │
│ 홈           ├──────────────────────────────────────────────────────────────┤
│ 자산          │ [총자산] [금융자산] [실물자산] [기타자산]                  │
│ 투자          ├──────────────────────────────┬───────────────────────────────┤
│ 지출          │ 자산 유형별 비중             │ 자산 추이                     │
│ 현금흐름      │ [Donut / Legend]             │ [Line Chart]                  │
│ 부채          ├──────────────────────────────────────────────────────────────┤
│ 보고서        │ 전체 | 예금/현금 | 투자 | 부동산 | 보험/연금 | 기타          │
│ 설정          │ [유형 ▼] [금융기관 ▼] [검색                   ] [필터]       │
│              ├──────────────────────────────────────────────────────────────┤
│              │ 자산명 | 유형 | 명의 | 금융기관 | 현재가치 | 전월대비 | 비중 | ⋯ │
│              │ ---------------------------------------------------------- │
│              │ 생활비 통장 | 예금/현금 | 민준 | 샘플은행 | ...             │
│              │ 장기 적금   | 예금/현금 | 서연 | 샘플은행 | ...             │
│              │ 투자 계좌   | 투자      | 민준 | 샘플증권 | ...             │
│              └──────────────────────────────────────────────────────────────┘
└──────────────┴──────────────────────────────────────────────────────────────┘
```

PC에서는 자산 목록을 기본적으로 테이블로 제공한다. 자산 행을 선택하면 상세 Drawer를 열어 현재 목록 맥락을 유지한 상태에서 상세정보를 확인한다.

├─────────────────────────────┤
│ 생활비 통장          18,500,000 │
│ 예금/현금 · 민준 · 샘플은행   > │
├─────────────────────────────┤
│ 투자 계좌            56,800,000 │

## 7. 영역별 상세 명세

### 7.1 자산 요약

표시 정보:

- 총자산
- 전월 대비 증감 금액
- 전월 대비 증감률
- 금융자산 합계
- 실물자산 합계
- 기타 관리대상 자산 합계

투자자산은 총자산에 포함하되 투자 화면과 중복 합산하지 않는다.

자산 분류 명칭과 상위 집계 분류는 실제 자산유형 기준정보 설계 시 최종 확정한다.

### 7.2 자산 유형별 비중

표시 정보:

- 자산 유형 또는 상위 자산군별 금액
- 총자산 대비 비중
- 합계 금액

PC에서는 Donut Chart + Legend 조합을 기본 시안으로 한다. Mobile에서는 화면 폭에 따라 축약된 Donut 또는 유형별 요약 목록으로 표현할 수 있다.

### 7.3 자산 추이

표시 정보:

- 기간별 총자산 변화
- 기준일 또는 기준월

자산 추이의 기본 조회기간 및 스냅샷 생성 기준은 `SCR-012 순자산 추이` 및 자산 평가 정책과 함께 확정한다.

### 7.4 자산 유형 탭

주요 유형을 빠르게 전환할 수 있도록 상단 탭을 제공한다.

예시:

```text
전체 / 예금·현금 / 투자 / 부동산 / 보험·연금 / 기타
```

정확한 탭 구성은 시스템 관리자 페이지에서 관리되는 자산유형 및 상위 분류체계 확정 후 결정한다.

### 7.5 검색 및 필터

PC와 Mobile 모두 다음 조회 조건을 지원하는 방향으로 설계한다.

- 구성원
- 자산유형
- 금융기관/보유기관
- 자산명
- 계좌 또는 식별정보 검색
- 활성/비활성 상태

초기 화면에서는 활성 자산만 기본 조회한다.

### 7.6 PC 자산 목록

PC 기본 표현은 테이블이다.

후보 컬럼:

- 자산명
- 자산유형
- 명의
- 금융기관/보유기관
- 계좌 또는 식별정보
- 현재 평가금액
- 전월 대비 증감
- 총자산 내 비중
- 최종 갱신일시
- 상세 메뉴

컬럼 수가 과도해질 경우 우선순위가 낮은 정보는 상세 Drawer로 이동한다.

### 7.7 Mobile 자산 목록

Mobile에서는 카드/리스트 형태로 표시한다.

필수 노출 정보:

- 자산명
- 자산유형
- 명의
- 현재 평가금액

선택 노출 정보:

- 금융기관
- 전월 대비 증감
- 최종 갱신일시

카드를 선택하면 자산 상세로 이동한다.

## 8. 자산 상세

### 8.1 PC

PC에서는 자산 목록 행을 선택하면 우측 `Drawer`에서 상세정보를 조회한다.

기본 표시 후보:

- 자산명
- 자산유형
- 명의
- 금융기관/보유기관
- 계좌/식별정보
- 현재 평가금액
- 평가 기준일
- 최종 갱신일시
- 메모
- 유형별 추가정보

본인 자산인 경우:

- 수정
- 비활성화

다른 구성원 자산인 경우:

- 조회만 가능
- 수정/비활성화 버튼 미노출

### 8.2 Mobile

Mobile에서는 별도 상세 화면을 기본으로 한다.

PC Drawer의 핵심 정보를 세로 배치하고 본인 자산에 대해서만 수정/비활성화 동작을 제공한다.

### 8.3 거래/변경 이력

자산 상세 화면에서 거래이력 또는 평가금액 변경이력을 직접 제공할지는 추후 도메인 설계 후 확정한다.

## 9. 자산 등록/수정

### 9.1 PC

입력 항목이 일반적인 수준인 자산 등록/수정은 `Modal`을 기본으로 한다.

입력 단계가 많거나 특정 자산유형의 입력정보가 복잡해질 경우 별도 화면으로 전환할 수 있다.

### 9.2 Mobile

자산 등록/수정은 별도 화면으로 제공한다.

### 9.3 공통 입력항목 후보

- 자산유형
- 자산명
- 명의
- 금융기관/보유기관
- 계좌 또는 식별정보
- 현재 평가금액
- 평가 기준일
- 메모

`명의`는 현재 로그인 사용자를 기본값으로 하며 일반 사용자가 다른 구성원 명의의 자산을 대신 등록할 수 없도록 한다.

### 9.4 유형별 추가 입력항목

자산유형에 따라 만기일, 금리, 부동산 주소, 연금 유형 등 추가 필드가 필요할 수 있다.

공통 필드와 유형별 추가 필드의 정확한 구조는 도메인 모델 설계 전에 별도로 확정한다.

## 10. 자산유형 및 권한

- 자산유형은 시스템 공통 기준정보로 관리한다.
- 자산유형의 등록/수정/비활성화는 특정 시스템 관리자 권한만 수행할 수 있다.
- 일반 사용자와 가계 대표자는 활성 자산유형을 조회하고 자산 등록 시 선택만 할 수 있다.
- 기존 자산에서 사용 중인 자산유형이 비활성화되어도 과거 데이터의 유형 정보는 유지한다.

## 11. 비활성화 정책

- 자산 물리 삭제 기능은 제공하지 않는다.
- 사용 종료된 자산은 비활성화한다.
- 비활성화 자산은 기본 자산 현황 및 현재 총자산 집계에서 제외한다.
- 과거 보고서나 이력에서 이미 참조된 데이터는 유지한다.
- 비활성화는 해당 자산의 당사자만 수행할 수 있다.
- 재활성화 허용 여부는 추후 도메인 정책에서 확정한다.

## 12. 금액 갱신

자산의 현재 평가금액은 자산 유형에 따라 갱신 방식이 달라질 수 있다.

후보 방식:

- 사용자 수동 입력
- 외부 API/시세 자동 조회
- 거래 데이터 기반 자동 계산

초기 구현에서 어떤 자산유형을 수동/자동 갱신 대상으로 할지는 추후 자산 유형별 정책에서 확정한다.

자동 조회 값을 사용하는 경우 화면에 최종 데이터 조회일시를 제공한다.

## 13. 데이터 상태

### Empty

```text
아직 등록된 자산이 없습니다.
첫 자산을 등록하고 차곡을 시작해보세요.
[자산 등록]
```

### No Result

```text
조건에 맞는 자산이 없습니다.
필터 또는 검색어를 변경해보세요.
[필터 초기화]
```

### Loading

- 상단 요약은 Skeleton Card를 사용한다.
- 자산 목록은 Skeleton Row/Card를 사용한다.
- 전체 화면을 하나의 Loading 화면으로 막지 않는다.

### Error

- 자산 데이터 조회 실패 메시지를 제공한다.
- 재시도 동작을 제공한다.

### Partial Data

외부 시세 등 일부 자동 평가 데이터만 조회에 실패한 경우:

- 정상 조회된 자산은 그대로 표시한다.
- 마지막 정상 값을 사용할 수 있는 자산은 마지막 정상 값을 표시한다.
- 해당 자산에 데이터 기준일시를 명확히 표시한다.

### Permission Denied

현재 가계 접근 권한이 없거나 허용되지 않은 자산 조회 요청인 경우 자산 정보를 노출하지 않는다.

## 14. 금액 표시

- 원화는 천 단위 구분자를 사용한다. 예: `18,500,000원`
- 금액 계산과 저장 과정에서 임의 반올림하지 않는다.
- 화면 공간을 이유로 원본 금액을 `1.8천만`, `4.1억` 등으로 대체하지 않는 것을 기본으로 한다.
- 계산 및 API/DB 정밀도는 `04-feature-requirements.md`의 `BigDecimal`, `DECIMAL/NUMERIC` 원칙을 따른다.

확정된 두 번째 시안의 디자인 언어를 기준으로 한다.

- PC는 테이블 중심
- Mobile은 카드/목록 중심
- 상단 자산 요약 및 자산 유형별 비중 제공
- 검색/필터 제공
- PC 상세는 Drawer
- PC 단순 등록/수정은 Modal
- Mobile 상세/등록/수정은 별도 화면
- 밝고 간결한 차곡 공통 디자인 유지
- 샘플 이름과 금융정보는 가명/샘플 값 사용

## 16. 확정 및 추후 항목

### 확정

- 두 번째 자산 현황 시안을 기준 디자인으로 사용
- PC 자산 목록: 테이블 중심
- Mobile 자산 목록: 카드/목록 중심
- PC 자산 상세: Drawer
- PC 단순 등록/수정: Modal
- Mobile 상세/등록/수정: 별도 화면
- 자산 물리 삭제 없이 비활성화 정책 적용
- 같은 가계 구성원 자산 조회 허용
- 자산 등록/수정/비활성화는 당사자만 허용
- 자산유형은 시스템 관리자만 관리
- 화면 시안/문서의 이름·자산명·금융기관 등은 가명/샘플 데이터를 사용하고 실제 구현에서는 DB/API 값을 사용

### 추후 확정

- 자산 상세 거래/변경 이력 제공 범위
- 자산유형별 수동/자동 금액 갱신 방식
- 공통 입력필드와 유형별 추가필드 구조
- 비활성 자산 재활성화 정책
- 자산 추이의 기본 조회 기간 및 스냅샷 생성 기준
